## Transcript interpretation

Each turn retains the request that established its context level separately from aggregate usage and turn timestamps. The derived cache preserves its timestamp, lifetime, pricing class, service tier, and cached-read flag. The session list uses bounded metadata before a session is parsed. Deferred enrichment retries missing turn facts within 16 MiB. Accepted parsed windows replace metadata answers, including unavailable context after compaction.

Cache state compares compaction time with the context request's time. Tool results and synthetic responses can advance the turn's end without another model request. Context level, window, and model still follow the turn's end.

Recent Codex `compacted` records can carry exact request usage in `latest_token_usage_record.usage`. Exact usage starts without model, provider, or service tier. Following matching-turn settings fill that compaction's billing identity before its turn closes. Settings after that turn describe another request. Cumulative usage fields cannot price that request.

A Codex compaction can write a `token_usage_record` followed by `compacted` and an explicit zero-token `token_count` snapshot. The session-cost report counts each unique response id as a billed request and drops the zero-token snapshot. Other `token_count` records have no response id. The report retains them as separate evidence. The [CLI reference](cli-reference.md#quantities-and-missing-coverage) defines recorded usage reconciliation and unknown coverage. A rollout without bills uses snapshots as a legacy fallback. `pricedCostUsd` excludes legacy fallback estimates, which appear in `estimatedCostUsd`. Request-derived metrics stay unknown when request coverage is unknown. The following thread setting updates only the response id named by the compaction. A bill missing required usage counters retains its known counters and remains unpriced until a complete record for the same response arrives.

Codex can repeat a `token_count` snapshot without running another request. The usage reducer suppresses a record only when both its request usage and cumulative usage equal the preceding complete snapshot in the same turn. Missing cumulative counters, cumulative advances, and new turns remain distinct requests. The bounded previous snapshot persists with incremental project-spend state.

Main and delegated turns retain usage grouped by each request's pricing identity. Cost warnings stay hidden when legacy or incomplete data cannot supply those exact identities.

## Parsing and attribution constraints

- A Claude response can occupy several transcript lines that repeat the same usage object. Usage is counted per response message, not per line.

- A Claude advisor consultation is its own request of the advisor model. Its request key names its response and its position in `usage.iterations`. It belongs to the agent that called it, so a subagent's consultation is that subagent's work. It counts in cost, request totals, and per-model subtotals. An advisor consultation can record cache reads and writes. It stays outside executor context, cache-expiry adjacency, and compaction figures. Cache-write warnings exclude advisor consultations. A response's context is its last executor pass. A subagent's model is the heaviest model of its executor requests. An iteration of an unknown type leaves that response's cost partial.

- A Claude request on Amazon Bedrock names the first-party model, an empty `inference_geo`, and no `requestId`. Only its `msg_bdrk_` message id marks it as Bedrock. The inference profile sits in the newest `model` attachment, at `attachment.identity.modelId`, and each `/model` switch writes a new one. The usage reducer keeps that profile in its saved state, so a resumed read prices an appended request by it. ## Project cost integrity scheduling

`transcript.ts` allocates at most 256 transcript directory watches, with warm-source folders first and sorted paths within each tier. A mixed folder keeps warm priority while any source is warm. Catalog refreshes update allocation after integrity classification. Selection reuses that allocation until the next catalog refresh. Folders beyond the limit retain warm and cold checks, including discovery of new files and directories.

`scheduler.ts` owns independent Project cost integrity deadlines and retained pass positions. Warm sources include open, running, incomplete, newly discovered, and recently changed files, regardless of archive membership. Selection, running activity, unarchive, file events, changed discovery, and dependency reconciliation promote affected paths for seven days. Warm passes start every thirty seconds. Cold passes rotate through remaining sources with a fifteen-minute target and request discovery of new files and directories. Each queue retains one pass and one owed rerun. Targeted work shares the global batch limit of sixteen asynchronous stats without restarting either deadline. Fresh Codex revisions also update the listing stat cache. Hidden panels pause both queues and close watches. Reopening starts with warm sources. Workspace changes and disposal reject pending checks.

Successful checks identify the accepted file revision and physical source independently of parse timestamps. Project cost age uses the oldest successful check across complete displayed sources and discovery. These sources also cover accounting dependencies with no current-period contribution. Discovery coverage identifies source membership accepted by the displayed snapshot. Snapshot preparation retains its opening membership evidence through publication. Newly discovered sources retain the previous age until their accounting is published. An empty ledger uses successful discovery time. Unknown coverage has no age. Revision-keyed evidence survives accounting-only record copies. Snapshot preparation removes evidence outside current membership and its displayed sources. The previous snapshot retains its successful evidence until preparation completes. A cooperatively prepared minimum index updates coverage in logarithmic work per checked source. Unchanged checks publish age updates without aggregation. Failed permission, lock, or I/O checks retain figures and successful check times. Confirmed missing paths alone establish absence. The existing Updated slot retains successful age while refresh work waits or fails. Replacement source identities invalidate dependent Claude accounting supplements. The supplement reader checks each opened dependency through its descriptor with the shared bigint revision conversion in `filerevision.ts`. It checks dependency paths again before admitting a supplement. Failed partial replacements retain complete lifetime figures for the session list and dispatched cards. Dispatched completion remains pending until replacement indexing completes.

The project-spend index reads a source in slices with a byte budget, so a slice can stop inside a line. An incomplete record keeps the bytes of that unfinished line once, as base64 in `pendingBytes`, and leaves `trailing` empty. Every reader of `trailing` checks `complete` first. A record that holds more than `PROJECT_SPEND_HELD_LINE_BYTES` of one line returns to the front of the index queue. The slice that ends that line stops at its end, and the file then goes to the back of the queue. When another record of the index takes a long line, every other record that holds one releases its bytes and reads that line again later. So at most one record of the index holds such a line. A held line stays in the extension host heap until its record releases it or the line ends, so this bound keeps long held lines from adding up across records. The ledger save holds one record text at a time and writes the texts in batches through `writeFileStreamAtomically`, because the ledger file can exceed 100 MB.
