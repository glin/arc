# Accounting

## Accounting contracts

Keep source ownership, recorded request coverage, and supported pricing separate. A priced subtotal establishes neither complete coverage nor a provider invoice. Codex billing `thread_id` identifies the source. Billing `session_id` can name its root parent. Foreign-thread bills supply uncertainty evidence without local dollars. For CLI reports, missing `thread_id` permits scoped pricing with unknown ownership. Reconcile cumulative snapshots and delayed bills before selecting report windows. Conflicting complete revisions remove their price.

[`reconcileCodexCosts`](../extension/src/sessioncost.ts) owns interval coverage, resets, trusted anchors, and ambiguous clocks. Unresolved compactions and counter resets do not invalidate earlier reconciled segments. A reconciled explicit baseline closes earlier open uncertainty in source order. Incomplete metadata supplies no coverage boundary. [`CLI quantities and missing coverage`](cli-reference.md#quantities-and-missing-coverage) owns the exact compaction-offset matching contract and public coverage meanings. Those rules describe observed recorded counters, not a documented provider guarantee.

## Cost and context

Price usage by its recorded provider, model, inference class, service tier, and request context band before adding dollars. A model name alone establishes no provider. `resolveModelPricing` and `quoteUsage` in [`pricing.ts`](../extension/src/pricing.ts) own supported identities, route prefixes, rates, multipliers, and fallback windows. Unsupported combinations remain unpriced. A recorded amount takes precedence over recalculation. Tool calls establish no billable tool fee without a provider-recorded billable count.

Request bands must survive turn, child, checkpoint, export, and daily aggregation. Aggregate input cannot establish which requests crossed a threshold. Each Claude executor pass selects its band from its own input, including cache reads and writes. Input exactly at the threshold retains the base rate. One response remains one executor request. A recorded response cost counts once. Claude Code's aggregate pricing can differ from this per-pass calculation. Completed linked print results retain their recorded costs because they contain no pass breakdown.

Count a Claude response once across repeated content blocks. A growing child response replaces its earlier usage. Parent reads retain the first response occurrence. Advisor consultations in `usage.iterations` count as separate requests at their own model rates. They belong to their calling agent. They remain outside executor context, cache-expiry adjacency, compaction figures, and cache-write warnings. Unknown iteration types make response cost partial. Codex input includes cache reads and writes, so readers split these categories before pricing.

Panel session and turn estimates retain safely attributable priced usage when other usage is unavailable. `+` marks a lower bound. Ownership-uncertain usage contributes no dollars. Missing-only usage leaves cost unavailable. Recorded zero remains zero. Incomplete source coverage and unavailable pricing remain separate facts. Lifetime projections exclude incomplete buckets whose counters cannot establish safe usage. Main-agent and delegated coverage qualify their respective scopes and suppress affected cache-write warnings.

Session headings read lifetime spend independently of parsed timeline windows. `turnCardCost` adds dispatched contributions to `turnCost` in [`turncard.ts`](../extension/src/turncard.ts). Cost detail uses the retained lifetime projection. Execution figures and Activity tool counts do not establish billing request counts.

## Context evidence

Context describes one request's retained input, not lifetime token volume. Preserve `contextRequest` separately from turn totals and end time. It carries the context-setting request's clock, cache lifetime, pricing identity, cached-read fact, output, and Claude effort and Bedrock identity. Claude uses the final executor pass. Earlier pass output already belongs to that pass's input. Tool results and synthetic responses can advance a turn's end without another request.

The recorded context window takes precedence over model metadata. A newer compaction with unknown replacement context removes current context rather than reusing an older level. A later measurement restores it. Next-turn pricing requires a finished successful request or usable replacement context from a newer compaction. Open requests leave later tool input unmeasured. Add only the context-setting request's output when pricing the next request.

`nextTurnFloor` prices cached and uncached input through the same request bands, route multipliers, tiers, and cache rates as recorded usage. Unknown service-tier pricing removes the estimate. Recorded lifetime takes precedence over the model's fallback. Without either, the prompt box shows the cold estimate and retains a differing warm amount in detail. The panel switches cold 90 seconds before inferred expiry. Request timing establishes no cache identity or guaranteed reuse.

A model selection preserves measured context but prices the selected model uncached against its advertised window. Unsupported selected pricing removes the estimate. A changed Claude effort also selects uncached pricing when the detected route rebuilds cache. Preserve the recorded write lifetime for that calculation. [`effortChangeKeepsCache`](../extension/src/pricing.ts) owns model exceptions and undetected routes. The next recorded turn restores runtime evidence. Session list cache marks use the same request lifetime and pricing evidence, with their presentation owned by [`railCacheMarkOf`](../extension/src/turnrail.ts).

Claude Context categories use native estimates. Messages opens only when its valid child estimates sum to Messages and the overall categories reconcile against positive used context. Child shares use all used context. Children remain included in Messages. Missing or mismatched message detail leaves category bars available. Native corrections can cap Messages below its estimated children.

Codex Context estimates retained plaintext at four UTF-8 bytes per token. Ordinary tool outputs remain unattributed because their saved text precedes live-context truncation. Complete compaction replacement histories supply retained tool text. Unattributed context also includes hidden input, media, opaque summaries, and estimation differences. Use the newest request's input plus output, or a post-compaction retained-context estimate. Cached input is already input. Lifetime usage supplies no category.

[`inspectCodexContext`](../extension/src/codexcontext.ts) owns category admission and measurement freshness. Repeated usage notifications cannot measure later input. Aggregate Context and Compact remain available when categories are unavailable. Codex supplies no compaction reserve. Saved inspection starts no agent and uses bounded worker reads.

## Compaction accounting

Codex compactions use exact recorded request usage when response identity and billing identity resolve. Cumulative counters alone cannot price a compaction request. Ordinary bills, token snapshots, compaction records, and saved checkpoints must join the response once. Missing response identity adds no separate priced request and leaves coverage incomplete. Following settings fill only the named compaction before its turn closes. Later settings describe another request.

Claude writes no compaction request usage. An estimate requires a paired boundary with summary size and an earlier main request naming a model. [`compactionEstimate`](../extension/src/pricing.ts) owns input and summary-output estimation.

Cold compaction estimates require recorded preceding lifetime expiry. Missing lifetime alone establishes no cold cache. The compaction's own lifetime remains unrecorded. A zero post-compaction cache read establishes an empty prefix only before five minutes pass with a recorded preceding lifetime. Otherwise the estimate keeps its fallback prefix. [`claudeCompactionPrefixRead`](../extension/src/transcript.ts) applies that rule. [`CompactionEstimateInput`](../extension/src/pricing.ts) defines the preceding-request and post-compaction evidence used by the estimate.

Session lifetime cost includes every supported Claude estimate, including estimates outside retained compaction detail. Main-session estimates also enter a turn only when compaction falls between that turn's responses and its next response arrives with summary size known. Estimates outside those responses belong to no turn. Child and dispatched estimates use their own last main request, excluding inline subagent requests. Project cost excludes Claude estimates and includes identified Codex requests once. Cached-input shares and write warnings exclude compactions. `Included above` reports overhead already counted. Its cost is partial when fewer compactions have prices than the lifetime count.

## Cache expiry

The panel classifies expiry before aggregation removes request order. A main-source return is the first request under a new visible prompt after the preceding full nominal lifetime. Native child sources also admit source-local returns within one prompt or without prompt identity. Never apply the 90-second forward-estimate margin retrospectively. Unknown lifetime, missing or backward clocks, incomplete requests, and missing main prompt identity leave the pair unavailable. Changes in model, provider, tier, inference geography, known effort, or known tool-list version exclude the pair. [CLI reports](cli-reference.md#quantities-and-missing-coverage) retain separate return categories and source coverage.

Claude records five-minute or one-hour write lifetimes. Read-only responses retain preceding lifetime. Unknown writing lifetime clears it. Mixed executor tiers establish the first writer's lifetime only with zero first-writer reads, one tier per writing pass, and full-prefix reads on every later pass. Tokens establish this inference, not cache identity. Codex generic writes occupy `cacheWrite30m` without recording lifetime. Its pricing row supplies timing when documented. Unknown timing remains unavailable.

An intervening compaction moves adjacency to its own clock. Invalid compaction clocks leave the pair unavailable. Revocation restores the preceding request or leaves an unknown intervening compaction. A compaction represented only by a changed count excludes the pair. A cold compaction already paid to resend old context, so the following request must not count that same gap again. [`CacheExpiryScan`](../extension/src/projectspend.ts) owns delayed requests, corrections, ordinal matching, and resumable carry.

Cost added prices resent context above its warm cache-read price, excluding new prompt text. [`cacheExpiryRebuiltUsage`](../extension/src/projectspend.ts) owns token allocation. Whole-request recorded prices cannot supply a category split. Incomplete or unpriced returns make amounts lower bounds. No priced return leaves money unavailable. Counts stay exact beyond retained return and compaction windows.

Main Claude cards match return request keys to opening response IDs. Codex cards match turn IDs. Native-child attribution requires verified ownership and finite clocks. Later prompts and accepted process ends cap its span. Recorded child work survives quiet expiry and host exit. A return after timed closure requires both work and return clocks beyond the shared closure margin. Dispatched sources stay outside this expansion. Main and child amounts warn independently at $1, including lower bounds. Child amounts sum within the parent span. Session figures carry no expiry warning sign.

## Delegated attribution

Native child transcripts supply primary lifetime usage for their own session and delegated usage for ancestors. Dispatch chains propagate through native and dispatched relationships. Count each physical source once per receiving session. Group dispatched contributions under the topmost dispatched session below that receiver. Catalog membership resolves dispatches. Removing a child from the catalog removes its contribution without a retained mark.

Dispatched work joins when its source group stops waiting. Queued incomplete reads, unfinished final lines, unresolved ownership, and open turns hold the group. Unfinished lines and open turns stop holding after their last write leaves the history limit. A skipped or absent source contributes retained usage without that waiting mark. The parent's safely attributable own usage remains available meanwhile, with delegated coverage partial. Final reply, interruption, error, or recorded process end closes a turn.

The first launch receipt assigns a dispatched session's whole lifetime contribution to one parent card, including later typed turns and recursive dispatches. Launches by that turn's subagents also count. [`countedDispatchReferences`](../extension/src/turncard.ts) owns assignment. A Claude print row keeps its amount. Subtract that amount only when settled primary-transcript pricing covers it. Its newest turn must start at or after the parent turn's start. Descendant dollars cannot establish this coverage. Otherwise omit primary-transcript usage from that contribution and mark it partial.

Completed Claude print results inside Codex commands establish ownership even outside the workspace. Failed or recognizable incomplete results retain an unpriced marker. Native Codex descendants contribute below missing ancestors, with ancestry partial. Cycles, conflicting ownership, absent metadata, incomplete sources, and copied history must not turn a partial child bill into an exact one. [`agentspend.ts`](../extension/src/agentspend.ts), `agentSpendDependencyKey`, and the provider reducers own recursive reads, shared refresh bands, and request replacement.

## Project cost

Index each transcript path once. Do not add parent-card child costs again. A linked Claude print result contributes when its transcript sits outside the workspace. Prefer a direct transcript only after it is complete and contains usable usage. Until then retain the linked result. Lifetime session attribution keeps that link independently.

Project windows use local calendar days across daylight-saving changes. Confirmed zero remains distinct from unknown or partial usage. [`publicProjectSpendPrice`](../extension/src/projectspend.ts) owns price precedence and effective-date selection.

The workspace ledger stores raw daily usage and separate lifetime buckets. Repricing does not rescan history. Workspace normalization lowercases Windows paths. macOS and Linux retain case. Canonical source paths resolve physical paths when available. Derived saved state must pass `parseSpendLedger`. Invalid records or display references reject the saved ledger. Older checkpoints retain totals only under their migration rules and rebuild before resuming. Parser generations must advance when changed saved accounting facts require unchanged files to rebuild.

Background indexing preserves the complete Project cost display while scans resume. Lifetime figures retain complete source fallback and safely attributable usage separately. Appends resume saved offsets. Truncation, replacement, lost repeated-record state, or incompatible parser identity rebuild the affected source. Persist scan progress and complete display records independently. Filtering progress to reconstruct display drops complete figures during rescans. One slice uses at most 1 MiB or 15 milliseconds, with a new timer turn between slices. A synchronous record parse cannot yield.

`arc.projectCost.historyDays` skips sources by their own modification time, including children. Default zero reads all history. Saved skipped usage still contributes. Windows beginning before the cutoff remain lower bounds even when retained sources contain their usage. Windows inside it retain exactness subject to other coverage defects. A skipped missing source preserves other known lifetime usage with incomplete coverage. Settings changes reoffer sources. Confirmed missing files retain derived figures while they contribute to retained windows.

Saves wait thirty seconds from the first unsaved change. Failed saves remain owed, log `projectSpendSaveFailed`, and retry from two seconds with doubling waits for five tries. Further changes or flushes restart eligibility. Workspace changes and disposal flush owed saves. Failed flushes do not retry after that lifetime ends. Crashes and reloads lose reads since the last successful save. Startup rereads saved offsets. A source deleted before its first successful save loses those figures.

## Project cost integrity scheduling

[`IntegrityScheduler`](../extension/src/scheduler.ts) separates warm and cold deadlines. Warm includes open, running, incomplete, new, and recently changed sources regardless of archive state. Selection, activity, unarchive, file events, discovery changes, and dependency reconciliation promote paths for seven days. Warm passes start every thirty seconds. Cold rotation targets fifteen minutes and requests discovery. Each queue retains one pass and one owed rerun. Targeted work shares sixteen asynchronous stats without resetting deadlines. Hidden panels pause checks and close watches. Reopening starts warm. Workspace changes and disposal reject pending results.

Directory watches cover at most 256 directories, with warm folders first and sorted paths within tiers. Any warm source keeps its folder warm. Catalog refresh reallocates watches. Selection reuses that allocation. Unwatched folders retain integrity and discovery checks. [`watchDirs`](../extension/src/transcript.ts) owns allocation.

Successful age uses the oldest accepted physical revision check across displayed complete sources, their accounting dependencies, and successful discovery. Parse time does not supply this age. An empty ledger uses discovery time. Unknown coverage has no age. New membership retains previous age until its accounting publishes. Failed permission, lock, and I/O checks retain figures and prior successful times. Only confirmed missing paths establish absence. Unchanged checks update age without aggregation. [`SpendCoverage`](../extension/src/projectspend.ts) owns membership and revision evidence.

Payload reads use immutable snapshots without aggregating files. Background builds retain complete display inputs and workspace epoch. Obsolete results never publish. Ledger, hydration, settings, pricing, and calendar changes invalidate builds. Workspace changes immediately show unknown values. Each build retains tomorrow's projection. Midnight publishes a matching projection or unknown amounts, then rebuilds. Session-list answers and dispatched updates publish independently. Partial replacements retain complete lifetime fallback until replacement indexing finishes. [`panelhost.ts`](../extension/src/panelhost.ts) owns snapshot publication and calendar scheduling.
