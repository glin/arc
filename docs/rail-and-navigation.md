# Session list and navigation

Read this document when changing session selection, grouping, search entry, file links, context menus, or where editor content opens.

## Session list

`turnrail.ts` turns session rows into session list rows and time buckets. Pinned sessions lead the list. Active work rises ahead of inactive work without shuffling on every activity event. Archived sessions live in their own folded bucket.

At widths where the session column fits, the session list is permanent application structure. Its launcher, filter, and landmark remain present when the project has no session rows or only a single row. The browser decides between the wide session list and compact navigation from the shared breakpoint, never from the row count. Crossing to a narrow width and back restores the same wide session list and selected draft.

The session list fills the panel from its top to the status bar, even with zero or one session row. It uses the sidebar background across that full height.

The session list lists sessions from both agents in recorded activity order. Agent-run sessions use their own folded bucket. Selecting, pinning, or archiving changes presentation, not transcript discovery.

The selected session is stored by session id. Titles are display text and can change, so no action or saved state keys a session by title.

Full session cards show estimated cost first, whole-session turn count second, and current context third on a dedicated line. Cost includes the main session and delegated work associated with it. Turn count covers the main session only, so delegated work increases cost without adding turns. Both whole-session figures come from the persisted incremental spend index and remain absent until their required sources are complete. Selecting a session never changes them. Context uses parsed session facts when available and otherwise falls back to the same bounded metadata tail that supplies title and status, so the session list adds no transcript read. A tail that cannot establish the newest turn supplies no context. Missing figures leave no placeholder or extra gap. The figures are non-interactive spans inside the session button, and each carries its detail in a native hover. The figures add no controls. [Keyboard and screen-reader contract](#keyboard-and-screen-reader-contract) defines session list navigation.

A running card shows the current turn's elapsed time inside the running word from the first minute. The card uses the earliest active recorded turn start or busy-child start and omits the figure when neither source exists. Its read-only figure hover shows the start and last activity clock times. Needs input shows no running figure.

The turn count stays on a full card's figure line. Session list metadata identifies the agent, state, and recency. The session list and open session heading show the same whole-session cost and main-session turn count. Both draw it as a figure in the interactive row. The session list keeps it second, after cost, and the session heading's own row leads with it, ahead of files, context, and cost. Until the lifetime index has a complete count, the figure is absent from both rows. The turns figure's hover on the session heading also carries the session's span, its compaction count where the ledger has them, and how many of its turns are actually drawn when that is fewer than the whole count. The heading disclosure opens and closes only the turn cards shown, and its action names that smaller scope.

Every metric added to a session list card must have a selection-independent source that covers the scope its caption claims. A current or tail-scoped value needs both parsed and metadata paths: cache source facts in the derived session entry, never a formatted chip, calculate display values when the session list is built, and let the ordinary parser replace the metadata answer. A whole-session aggregate belongs on the persisted incremental index instead. If neither source covers that scope, omit the metric. This keeps future file, commit, token, or other session details from appearing or changing only after the session is selected.

`turnlabels.ts` owns the reader's labels. A label is a word the reader puts on a session. One session carries several. A label is the reader's own opinion of a session, not a fact read from a transcript. A full card that carries labels draws them as outlined chips on their own line under the figure line. A card with no label draws no such line. The card draws the first few chips and folds the rest into a count. The accessible name says every label, including the folded ones. Folding is a drawing limit, not a claim about what the session carries. The chips are non-interactive spans inside the session button, so the labels add no controls.

The View menu's `Rows` row chooses between two densities for every session list card at once, `Full` and `Compact`. The choice is saved as `railDensity` beside `railWidth`, outside any saved filter or saved view, so it survives across every filter and every restored tab. Full is the default and keeps a card's figure line, its label chips and its agent word in the drawing where the card carries them, except that a row under an agent group leaves its agent word out. A compact card is one line: the name, then a state slot that never shrinks. The slot holds the status word, and a running card adds its duration after its first minute, such as `running 2h 14m`. A running card with no recorded start draws `running` alone. The unsent word sits beside the status word on any card with a waiting draft, taking the age's place when the card carries no status word. Where no draft waits, the short age fills the slot for a card with no live status, and a failed card draws its word and its age together. With no time slot the cache mark is drawn before the unsent word, and where the time slot shows, the cache mark follows the age instead. An unread card adds the unread dot at the row's middle, and a card with a live cache adds the cache mark. A compact card drops the figure line, the label chips and the agent word from the drawing. A compact card's hover is a card of its own, drawn into the hint box. It opens once the pointer rests on the row for the editor's hover delay, 500 ms on Windows and Linux and 1500 ms on macOS. It shows the session's full name, then a meta line. The meta line holds the agent, the agent-run word where the card carries one, the status word, the unsent word and the long age, such as `Claude · needs input · 10 mins ago`. A running card with a recorded start shows no age. Its status word reads `running` in the run's first minute and adds how long it has run after that, such as `running for 31m`. A running card with no recorded start shows `running` and the age. A subagents or background card shows no age and adds its explanation under the meta line. The full card's figure line follows, drawn by the same component: the cost with its `+` and its warning sign, the turns and the context. The figures take no pointer and open no popover. The labels close the card as chips, eight at most before a `+N more` chip. A card's accessible name is the same string in both densities. Its accessible description carries only what the name does not already say. A compact card's dropped words stay out of it, and a subagents or background card's explanation stays in it. A compact card prints the age in short units with no `ago`, such as `now`, `10m`, `1h`, `3d`, `2w`, `4mo` or `1y`, where a full card prints the long form. Only the accessible name keeps the long form in both densities. The age's own hover gives the full local time, and the clock alone for a session from today. On hover, or with a control focused from the keyboard, a compact row's controls cover its metadata rather than its name, so pin, archive and label actions appear without moving the name. Where the metadata is narrower than the controls, such as a short age and a cache mark, the name ends before the controls. A compact row also keeps the state border colour, the unread dot and its name weight, the shown-session tint, and the archived dimming that a full row draws.

A session list row carries both lists. `labelChips` is the cut the row draws and `labels` is every label the session holds. The filter answers a `label:` term off the whole list.

The panel starts a session under a provisional id and learns the durable id when the agent accepts the first prompt. Adoption moves labels, pinned state, and archived state to that durable id. A bounded alias routes delayed actions from the provisional shell to the durable session. Browser replies keep the provisional identity until a complete render names their exact identity mapping. The Prompt box, the timeline heading, and the session list's label editor adopt at that render. An open label editor then stays under the heading drawn for the durable id and writes labels for that id. A press or a label reply that still names the provisional id reaches the same editor. An incremental session list update projects a durable row onto that shell only when it carries the same mapping. Otherwise, the panel retains its last coherent provisional row. The provider owns durable pinned and archived membership, including native menu changes and delayed browser saves. `sweepDraftLabels` drops abandoned provisional entries when stored state is first read. Normalization must never call it because a live draft's labels have to survive every write.

The extension owns the label state. Each card arrives holding the chips it draws and the full name of each on its hover, so the panel keeps no copy of the record. A state save posted by the webview carries no labels, so an older copy in another tab cannot overwrite them. The session list's cards are the only place the record reaches the panel, so the session heading reads its labels off the session list row for the session it draws. The session rows the rest of that heading is built from carry none.

The session heading in the main timeline view draws the same labels on a line of its own, under the heading's figure chips. That line draws every label the session carries and never folds, because it has the width of the panel where a card has the width of the session list. It is drawn whether or not the session carries a label, and the press at the end of it reads `Labels` or `Add a label` accordingly. Each chip there is a button, and a press writes the term that files that label into the session list's filter box and leaves the focus in it. The reader keeps the session open in the session view, while its session list card follows the active filter.

Below the session list breakpoint, heading label chips become spans with native tooltips and no keyboard stops. Crossing the breakpoint redraws the label line. The navigation owner transfers its stop and focus to the replacement element. New label buttons enter the roving walk after creation.

A session list card's chips stay spans at every width. The card is itself one button, and a button cannot hold another.

A popover edits one session's labels. It holds a find-or-create box, then a checkbox for each label the workspace has with the count of sessions carrying it. A name that matches no label offers to create it, and one press creates it and applies it. These controls open the popover: a third action on the session list card's hover row, `L` on a focused card, the card's context menu, the press on the session heading's label line, and the session heading's context menu. Below the session list breakpoint the session heading's line press and its context menu are what remain. A session list card with no parsed turn names a section of its own, because filing a session needs no newest turn, while the read entries go on gating on the two read sections.

A saved session's session list card and session heading offer Rename… in their context menus, and offer it while the session's turn runs. A provisional new session has no saved record, so neither its card nor its heading offers it. A session list row projected onto a provisional id before the adopting render does not offer it either. The card and the heading tell the menu through a `sessionPersisted` context value. The command reaches every open panel, and only the panel that saw the right-click opens the editor. It opens next to the control the menu came from: the session list card, the heading's three-dots button, or else the heading's disclosure. The editor holds one name box that starts from the session's full name, not the shortened card text, with Cancel and Save name. Enter saves and Escape cancels. A sent rename cannot be taken back, so the box, Cancel, and Save name hold still while it runs. Focus stays in the box after a press on Save name. Escape, a press outside, and any other session list popover still close the editor, so two popovers never float at once. The rename then still finishes. Each rename carries a request id that a reloaded panel does not reuse, and the host answers every rename with that id. An answer that finds no editor, or finds the editor waiting on a later rename, changes nothing. A session that leaves the session list closes its editor. Success closes the editor. A failure keeps the typed text and shows the reason under the box. Either answer moves focus only when focus is still in the editor. Success then returns focus to the card or heading control the editor opened from, or to the timeline when that card is hidden below the session list breakpoint. [Agent protocols](agent-protocols.md#session-rename) owns what each agent does with the name.

The panel requests label rows whenever the label editor opens and posts the complete name list for one session. The extension writes the record and checks spelling and limits. Creating a label remains subject to those checks. A write answers with fresh rows, and an open popover keeps the order it was given, so a box the reader ticks does not move under their hand. A fresh open takes the order the extension settled, which leads with the labels the session already carries.

Any write to the record tells every panel that something moved. A write carries a count on every label the workspace has, and it can add one or take the last holder off one. So a panel holding an editor open on another session asks again for its own rows, because the extension cannot know which session each panel is showing. The control the popover hangs off is found again by the session it names, so a session list rebuilt from nothing leaves neither the placement nor the focus return pointing at a control that has gone. It is looked for in the order the reader meets it: the session list card's control, then the heading's label line, then the heading itself.

The popover is the only place the reader is told two things no card shows. A comma inside a name reads as two labels when a card is read out. Two names that agree for the whole of the name ceiling are one label. Both notes appear under the box while a name that triggers them is being typed.

Bucket headings stay over the cards they name. The session list scrolls in its own column, so a heading rests below the session list header while its own cards pass under it. The panel measures the rows above the cards and writes the offset onto the session list, because they carry a project cost row only sometimes and their height is not one number.

A folded bucket keeps its heading and total count, while its rows are absent. [Keyboard and screen-reader contract](#keyboard-and-screen-reader-contract) defines group structure and focus recovery.

The session list filter accepts `agent:`, `title:`, `label:`, `cost:`, `cache-expiry:`, and `is:`. Bare words match title substrings. Labels match complete names with the shared case-folding rule. Double quotes enclose values with spaces. Two quotes inside a quoted value represent one quote. A leading `-` negates a term on any supported axis. Every positive term must match, and every negated term excludes its matches. For example, `label:ui label:bug is:active` keeps Active sessions carrying both labels. A lone `-` or a word starting with two negation marks adds no term. A word starting with a quote remains text. Thus `"-fix"` searches titles for the hyphen, and `find: "-name"` searches content for it. `is:` completes input, unread, read, running, warm, active, needsyou, archived, and agentrun. No complete value is a prefix of another. Incomplete and unknown status words add no term. `is:archived` reads archived state independently of Show archived. `is:agentrun` reads agent-run identity independently of the displayed bucket. `is:warm` tests prompt-cache lifetime against the browser clock, including archived sessions and agent runs. `is:active` tests that lifetime or activity within the last hour against the same clock. `is:needsyou` keeps sessions matching `is:active` that need input or are unread. `domain/session-query.ts` owns grammar, caret tokens, and matching. `view/session-query.ts` owns query notes and label suggestions.

`cost:>5.43` keeps a session whose recorded USD cost is greater than the threshold. `cost:<5.43` keeps one whose exact recorded cost is less than the threshold. A cost value requires one strict `<` or `>` operator followed by a non-negative whole or decimal number. A session with no recorded cost matches neither comparison. A lower-bound cost matches `>` only when its recorded amount already exceeds the threshold. It never matches `<`, because the unknown remainder can cross the threshold. A negated cost term keeps every session its comparison drops, which includes a session with no recorded cost and a lower bound that has not crossed a `<` threshold. An invalid cost value remains in the query, empties the session list, and receives a visible correction from the filter box.

`cache-expiry:>0` keeps sessions with more than zero exact cache-expiry returns. `cache-expiry:<3` keeps sessions with fewer than three. Values use the strict non-negative comparison grammar described for `cost:`. Unavailable or unindexed facts match neither comparison. A lower-bound count matches `>` only when its known amount exceeds the threshold. It never matches `<` because unclassified request pairs can increase the count. Negation keeps every session the positive comparison drops, including unavailable facts and lower bounds. An invalid value remains visible, empties the list, and receives a correction in the filter box. `sessionCacheFactsBySession` in `extension/src/projectspend.ts` supplies lifetime primary-session facts. The filter reads them from the Session list card without scanning requests. The card displays no cache-expiry figure.

The extension sends every label the workspace has, with a count on each and the words that say what the count counts, on the first render and with every session list update. The count joins the comparison that decides whether to post, so a label taken off its last holder leaves the box. The label editor and the filter box are handed rows of that one shape, so nothing in the browser holds a rule about when a count is plural.

A list under the box offers what the word under the caret asks for. A part of an axis name offers that axis, so one press writes `label:` with its colon. A `label:` word then offers exact label matches, prefix matches, and remaining substring matches in that order. Labels in the same match group keep the order the extension counted them. One press completes the label. An empty box offers nothing, because a list that opened as focus arrived would cover the session list. A press writes only the word under the caret, so a term completed inside a longer query leaves the words around it standing, and a name holding a space is written quoted. A word opening on `-` offers the same rows under the mark and writes it back, and the mark alone offers every axis. Those rows read as Filter out where the rest read as Filter by.

Filter completion keeps focus in the box. The combobox exposes `aria-expanded`, `aria-controls`, and `aria-activedescendant`. Options expose `aria-selected`. Up and Down move the active row. Enter and Tab accept it. Escape dismisses the list without changing the query. Dismissal applies to the current token. Moving to another token or reopening the box restores suggestions. Input-method composition retains its keys. Row and chip tooltips expose complete names when visible text is shortened.

The session list filter narrows the session list only. Its input updates are coalesced to an animation frame so a run of keystrokes does not reconcile the full session list for every browser event. Without an effective session list filter, an empty saved-view heading remains reachable for edit and delete. Content search is a timeline search and shows its own result list. Empty filter results say that the filter matched nothing without implying that transcripts are missing. Background structural updates preserve the session list's scroll position. Pinning a session deliberately scrolls to the top once.

Below the session list breakpoint, the sticky panel bar becomes the navigation surface. It holds a split new-session control at the left. A compact session picker follows when there is a choice, and Project cost follows when spend data is available. Transcript changes refresh the panel automatically. Ordinary panel updates reconcile the compact bar in place. While its native picker has focus, option changes wait until blur so activity in another session cannot dismiss the browser-owned dropdown.

The session list owner reports each visibility change to the existing chrome owner. This keeps the compact controls and Project cost face coordinated on initial data, session list-only updates, and live resize without transferring their DOM ownership to the session list.

Before the timeline measures its sticky heading offset, the chrome owner asks whether the accepted session list payload will be visible. The session list can draw afterward, but the compact bar must already have its final visibility when that measurement runs.

Project cost lists an agent only after indexed project records establish that agent. A recorded zero remains valid evidence, while an empty accumulator does not imply that the project used an agent.

The session list header has two rows. The action row holds the Sessions heading, magnifying glass, funnel, and New split. The heading leaves a session list narrower than 14.8em. Filter buttons occupy the next row after any notes and save-view action. Tab visits the action controls, then the filter buttons. Configured buttons appear during startup with unavailable counts and preserve the restored query's pressed state. After the authoritative list arrives, configured buttons appear with positive scoped counts or while selected, in Running, Active, Unread, and Needs input order. A selected button stays enabled and shows zero when no sessions match. Selection never adds an unchecked button. Each button draws its count and includes that count in its accessible name. Active adds an outline bolt while a matching session has a warm cache. It fills the bolt when a cache is about to expire. Its accessible name and hint detail describe that cache state. Buttons wrap at their boundaries. The magnifying glass opens the filter box, and the cross clears the query and closes it. Closing returns focus to the magnifying glass. Above 22.5em, the box shares a line with New. Below that width, it takes the next line. Escape dismisses completions first, then clears a nonempty query, then closes an empty box. Escape on a filter button leaves the query and box unchanged. A filter press preserves the box state. While the reader names a view, filter buttons hold their counts and cache information and refuse presses. Naming completion refreshes both. Payloads and saved-filter updates preserve the typed name. Restored panels leave the box closed.

Project cost follows every session list control at wide widths and precedes the session list. It stays with the head while sessions scroll. `#rail` stays the scroll owner. Its top scroll padding holds the measured head height, so a row reached from the keyboard stays below the head. The Project cost dialog opens below its session list button when that space fits a control or one text line. Otherwise, it uses the viewport and scrolls to keep controls reachable. The compact face stays at the top of the session view and keeps its own dialog placement.

## Saved filters

`domain/rail-filters.ts` owns saved session list filters. A saved filter records the query and sort order. Applying one narrows sessions before `railSections` assigns saved view claims and groups. It changes no saved view, section order, or remembered fold.

All sessions clears the query and restores the current session list default order. The workspace list does not store this built-in entry.

The Active filter button writes `is:active -is:archived -is:agentrun` into the query. Its lens excludes archived sessions and agent runs. The box shows those words, which the reader can edit. The button draws pressed while the query holds every lens word and no other complete lens. Word order does not matter. Deleting a lens word unpresses it. A pressed button removes its lens words and preserves other query words and sort order. Other filter buttons replace the current lens with their own words. A press over a saved filter makes the session list Custom. The selected button uses the hint `Show every session again`. After a press, focus goes to the selected button, else the first filter button, else the funnel. The same rule applies when configuration removes a focused button. A retained button keeps focus through payload and clock updates.

The View menu's Filter row sets All, Running, Active, Unread, or Needs input. Every value remains selectable without matches and draws its label without a result count. A Filter choice changes the query without adding an unchecked session list shortcut. Running writes `is:running -is:archived -is:agentrun`. Unread writes `is:unread -is:archived -is:agentrun`. Needs input writes `is:input -is:archived -is:agentrun`. A press writes its lens words, then removes words belonging only to another complete lens. All removes every complete lens and preserves other words, sort order, and selected filter identity. All is checked when the query holds no complete lens. Quick filters chooses the session list-head buttons through one checkbox per lens. The default choice ticks Running, Active, and Needs input. Panel state saves this choice as `railQuickFilters`. A legacy `railHeadLenses` choice loads with Running added. Toggling a checkbox keeps the menu open and focus on that checkbox. An unticked button leaves the session list immediately, including when its lens is selected. Forget State restores the default choice. A query containing two complete lenses keeps its typed meaning, checks All, and keeps its groups. All removes both lenses.

Unread and Needs input retain sessions the reader reads or answers. Each retained session must match the other query words and remain neither archived nor run by an agent. Changing the query or reloading the panel clears retention. Group by Status files retained sessions under their current state. Active and Running retain no departed sessions.

The Running lens keeps Running, Subagents, and Background sessions because `is:running` matches all three states. A session that stops running leaves on the next update. A bare typed or saved `is:running` remains a query term, and the funnel names it Custom.

The funnel opens the View menu. Its accessible name and hint detail identify the selected filter and current order. It fills for Custom, saved filters, and named lenses. It outlines for All sessions at the session list default. A query containing only one complete lens names the funnel for that lens. Additional words name it Custom. The menu holds find, Filter, Quick filters, Group by, Sort by, Rows, Show, Labels, Saved filters, and actions. The find box's clear cross is a stop in the menu's arrow walk while the box holds text. Every menu press keeps it open with focus on the pressed control. Escape or the funnel closes it and returns focus to the funnel. An outside press closes it and leaves focus on the pressed control, else the funnel. The magnifying glass owns opening the session list filter box. Filter, Group by, Sort by, and Rows draw radio pills. Sort by changes the default order on All sessions and the live order on a saved filter or Custom. A query or sort edit that differs from the saved snapshot makes the session list Custom without changing that snapshot. Save changes explicitly replaces it. Save as new, Rename, and Delete write the complete normalized list.

The extension owns the saved filter list in workspace state and sends it with each render or session list message. The panel owns the selected filter id, the live query and sort in its saved state. A panel saved by an older build opens with the Active lens it stored as the lens words. The old Warm words under All sessions open on the Active words, and an Active lens stored as session list state joins the query it was stored beside. The old Needs you filter id opens on All sessions with its stored query. A Needs you lens stored as session list state or on a saved filter loads as no lens and adds no word. A saved filter stored with the Active lens loads with the lens's words in its query, and a record saved again carries no lens. The load adds only the words the query lacks and keeps every word it held. The words narrow the way the lens did. A live `is:running` query stays typed text. The host omits the list from panel state saves, which prevents an older open panel from overwriting a newer list. The host checks the selected id of a save against the list it holds. A missing selected id falls back to All sessions. A stored filter under a built-in name, such as one the reader named Active before Active was a lens, keeps its query under that name followed by `(saved)`.

The find box narrows the label chips and the saved filters. Each label chip carries its count. The count leaves out every session that a Show row hides, so `railShownLabelCounts` in `view/rail.ts` takes those sessions off the workspace's label counts. The chips run from the most used label to the least, and a tie goes in name order. The menu draws the twelve most used chips and then a chip that reads `<n> more`. A press on that chip draws every label, and the chip then reads Fewer labels. The chips fold again when the menu closes. Text in the find box shows every label that matches it and draws no fold chip. `railMenuLabelChips` in `view/session-query.ts` owns this rule. A chip press adds or removes the label's term in the query grammar, and quotes a label that holds a space. A label the query already negates has no chip, because a press would write the term beside its own negation and empty the session list. The Filter row is the menu's only status control. The reader types any other status, such as `is:running` or `is:read`. Arrow keys, `Home`, and `End` walk the menu's controls. Native `Tab`, `Enter`, and `Space` behavior remains available. `Escape` closes naming or delete confirmation first, then closes the menu.

## Saved views

`domain/views.ts` owns the saved views. A view is a filter under a name. It holds its query and whether it keeps archived sessions. A view narrows the session list alone. Status, cost and cache-expiry terms are valid saved-view terms, and a view's membership updates as those facts change. Nothing in the extension reads a view to decide what to parse, so a view never changes which transcripts are read.

The session list draws one section per view. `railSections` in `view/rail.ts` puts them in one order: Pinned first, then the views in the order the reader saved them, then the groups over every session no view claimed, then Run by agents, then Archived. A view is a group of its own. A reader who wants one piece of work together saves the filter that finds it, and the session list draws a section under that name. Each view answers its query over every session the reader has not archived. Pinned holds its own copy first, so a pinned session that matches also appears in the view.

The View menu's Group by row chooses the groups, and the session list saves the choice as `railGroupBy`. Time draws Today, Yesterday, Last 7 days, and Older. Label draws one group per label, ordered by each group's newest session, then Unlabelled, which starts folded. Agent draws one group per agent, in name order. Status draws Needs input, Running, Unread, and Read, in that order. A waiting unread session sits under Needs input only, and a subagents or background session sits under Running. None draws one Sessions group. Under Label, Agent, and Status a pinned session sits under Pinned and again under its group. Under Time and None it sits under Pinned only. A session with two labels sits under both labels. Run by agents stays its own bucket under every value. A row under an agent group draws no agent word, because the heading names the agent.

An effective session list query filters cards before assigning saved views and groups. Matching sections retain their order, counts, sorting, and repeated copies. Empty sections leave the list while an effective query is active. Matching sections start open, including restored queries. Disclosure presses change temporary folds for that query. Query changes reset those choices, while payload and clock updates retain them. Clearing the query restores ordinary folds. Pinning during filtering opens temporary Pinned without changing its saved fold. Deleted saved views lose their ordinary and temporary folds. Search-only words such as `find:` and `in:` add no session list term.

Every section draws its first 200 rows and then a `Show 200 more` press, except Pinned, which draws every card the reader pinned. The press's accessible name adds the section, as in `Show 200 more in Today`. Each press draws the next 200 rows, and the last press names only the rows still left. A section also draws through the current session's row, rounded up to a whole step of 200, so the session the reader has open always has a row. The heading counts every card in the section, drawn or not. The press stays under the new rows, keeps the focus, and scrolls into view. The press that draws the last row goes away, and the focus moves to that row. A new query starts every section at its first 200 rows, and a query the reader returns to keeps its presses. A saved view whose query changes starts again at its first 200 rows. `RAIL_ROW_STEP` in `view/rail.ts` holds the step.

The session list default order is Latest update, Cost highest first, Cost lowest first, or Needs you first. It orders cards only after the session list has settled section membership and claims. A saved view can follow the session list default or keep its own order. Its heading tooltip and accessible name give the full explicit override, including one equal to the default. Cost orders leave unpriced sessions last. Needs you first ranks needs input, unread, running, subagents and background command, then read and idle.

A session two views match appears under both. Each view answers for itself, so a section's contents cannot depend on the order the reader happened to save its neighbours in. A view that does not keep archived sessions never sees one, and the Archived fold keeps the card either way.

Section headings use the time-bucket disclosure component. Keyed headings and group lists preserve surviving rows within their group. Every heading shows its count. Saved-view headings show their name and expose a reserved three-dot button on hover or focus. Session cards retain their cost figures, cost ordering, and `cost:` filtering. Without an effective session list filter, an empty saved view keeps its heading, starts folded, and reports no sessions. Applying an effective session list filter removes saved-view headings with no matching cards.

A view writes its fold under its own id rather than its name, so renaming a view keeps the fold the reader set. `normalizeRailFolds` accepts a time bucket's fold name and any key under the `railgroup:` prefix, and nothing else.

A saved view requires an effective query term. The save row draws only while the box holds one, so a query of `find:` or `in:` words alone offers no save. `domain/views.ts` owns the term gate.

Save as view opens the name field with its text selected. A stored query with exactly one positive label suggests its catalog name, or its parsed spelling when absent from the catalog. Other terms keep their restrictions. Multiple positive labels and queries without a positive label leave the name empty. Enter saves the name, typing replaces the selection, and Escape cancels. An existing view with the suggested name requires another name.

The extension owns saved views and excludes them from panel state saves. An older panel therefore cannot overwrite views created elsewhere. Save, rename, and delete each post the complete list in one message. The extension normalizes names and limits before publishing the list to every panel. Saved views participate in session list update comparison even when their changes move no card.

A saved-view heading opens the native menu from right-click, the keyboard context-menu route, or its three-dot button. The menu offers Edit view… and Delete this view. Edit view opens the existing name and order editor. Save and Cancel return focus to the opening control, including after a heading redraw. A time bucket carries no view actions.

## Read and status state

`turnread.ts` owns stable turn keys, the explicit read set, and session watermarks. The session list card alone receives the computed unread state. The session heading does not draw a count and carries none.

A session row takes its status from the newest parsed turn and from active child state. Error, completion, and explicit interruption keep their existing precedence. A durable Claude process end stops an otherwise unfinished turn before the one-hour silence fallback applies. The full parser, bounded metadata reader, and complete lifetime index retain the same boundary, so selection and reload do not change the word. Process shutdown does not move session list recency. Running belongs to each session rather than to the first row in a merged list.

A live permission request or question changes the row status to `waiting`. Waiting overrides `running` because the child cannot continue without the reader, but it stays in the active group so the session list does not shuffle repeatedly. The card and its accessible name both say `needs input`, read from one phrase `turnrail.ts` defines. `is:input` matches this state, while `is:unread`, `is:read`, and `is:running` match the other reader-facing states. This state comes only from an ask the live child holds. A request clears it when the request resolves or the turn ends. A Codex async question clears it when the question closes as the `delivery: async` paragraph in `docs/agent-protocols.md` describes.

A session list card paints running in the same yellow a running turn card wears, and needs input in orange. A card in the subagents state wears the running yellow edge and word. Its word is the live child count, and its hint says that the reader can send a prompt now. A card in the background command state wears the same edge and word. Its word is the count of commands the agent started in the background that still run, and its hint says the same. Blue stays with the unread mark alone. Unsent input uses the editor's modified-resource tone, matching the New draft chip because both mark unfinished work owned by the reader.

Marking a session read records its activity boundary. A later turn becomes unread. Marking an individual turn unread can override the session watermark without changing its neighbors.

## Keyboard model

The session list and timeline use separate keyboard models. [Keyboard and screen-reader contract](#keyboard-and-screen-reader-contract) defines entry, movement, group structure, resizing, and focus recovery.

Disclosure buttons carry `aria-expanded`. A folded bucket remains reachable and names what it contains. Archive, pin, and the label editor are real buttons with accessible names and visible focus.

A session list card takes `l`, `p`, and `Delete` on the session it names. The key handler also takes `Backspace` on macOS, where the hint names `Backspace` alone. It refuses the key on an archived session, which is what the pin entries on both context menus also do.

Pressable controls with information beyond their visible text use the panel hint instead of a native browser title. These controls include session list actions, both setup carets, the primary New action, and the session heading press. A hint gives the short action and optional key, then its effect when one exists. The session heading gives the full session title first and the action on every shown turn second. Pointer hover opens a plain hint after a short delay, and a compact card's hover after the longer delay the Compact rows paragraph names. Moving the pointer from an open hint to another control opens that control's hint at once. Moving it onto a compact card closes any open hint, including one that keyboard focus opened, and the card waits its full delay. Keyboard focus opens either one immediately. Pointer leave, focus leave, Escape, a press, session list scrolling, resizing, or removal of the control closes it. The spoken control name still includes the session title where the action belongs to one. Read-only text and rows inside an open popover keep native titles.

The label popover keeps its own walk. It sits outside the session list and timeline navigation scopes. Arrow keys, `Home`, and `End` move between the box, its cross, the create row, and the checkboxes. The cross shows while the box holds text. Pressing it empties the box and keeps focus there. `Space` and `Enter` toggle a focused checkbox. `Enter` in the box applies an exact existing label or takes the create offer. Plain `Tab` in the box applies the first visible unapplied existing label, clears the find box, and keeps focus there. `Tab` keeps its native walk when the box is empty or no unapplied existing label matches. `Escape` shuts the popover and returns focus to the control that opened it. The native find box stays mounted and uncontrolled while rows reconcile, which preserves its caret, undo history, and active input-method composition. Only an explicit reset clears it.

## Back and forward

`turnplaces.ts` holds the trail of places the reader visited. A place is a session. Content search runs from the session list box and draws its results in the timeline, so it opens no second kind of view and a place carries no query.

The provider stores navigation history across panel tabs. A window reload starts a new history at the restored session. Each panel retains its own visible session. Back and Forward move only the invoking panel. Every navigation route records its destination after `pickShowing` resolves the selected session. Session selection and history navigation share the same draft-abandonment rules.

A session that disappears is pruned from the trail, and neighbours that become the same session fold into one press. A draft keeps its place across the rename from its invented id to the one the agent reports.

Back and forward reach the reader by the mouse's fourth and fifth buttons, by the chords the editor binds to Go Back and Go Forward, and by two arrows in the Arc tab's own toolbar. Each route follows one rule. The panel's trail answers first, and a trail with nowhere left to go hands the press to the editor's own Go Back. That command has an end of its own, so a window whose only editor is the panel reaches both ends at once and the press does nothing.

The panel handles the fourth and fifth mouse buttons inside its webview frame. Workbench mouse listeners do not receive those events. The panel cancels both press and release events. It respects the editor setting that disables mouse back and forward navigation.

A navigation press is still an ordinary press to everything else on the page, so an open menu or a pinned float shuts under it the way it shuts under any other press.

## Files, commits, and editor groups

`turncard.ts` prepares file and commit rows. The panel displays normalized forward-slash paths but sends the recorded path back to the extension.

File rows open through the extension. Diff rows use the read-only URI providers in `uris.ts`. A normal press opens beside the panel in the file area. Repeated beside-open actions reuse the editor group created for that purpose. An explicit split action can request another group.

Links in rendered responses follow their destination, and the extension tests each target in one order. A directory is revealed in the Explorer. A picture opens through `vscode.open`, which reaches the editor's own viewer. A local `.html` or `.htm` file opens in VS Code's integrated browser. A local `.md` or `.markdown` file opens in Markdown Preview in the requested editor group. Every other local file opens in the text editor. HTTP and HTTPS links open in the configured external browser.

Integrated-browser placement follows `workbench.browser.newTabPlacement`. VS Code applies workspace trust to local HTML navigation.

Commit links open through VS Code's Git extension only when the repository directory is known and the command is available. A commit made outside the open workspace carries its repository name. An unresolvable repository leaves the hash as text rather than opening the wrong tree.

When Git reports the ref that created a commit, the row shows its named branch or says that the commit was detached. This distinguishes a temporary isolated-checkout commit from a later branch commit without merging rows that merely share a subject and statistics. A commit made in a worktree whose directory is named for that branch shows the branch and no place, and its hover still names the worktree.

The file icon comes from the active icon theme when it can be resolved safely. `fileicons.ts` supplies a text badge fallback. The icon is decorative. The accessible name comes from the file row text.

## Context menus and copy

Turn cards, session headings, session list rows, file links, and summary links identify themselves through context values. Menu enablement reads that context. The current selection elsewhere in the editor does not decide it.

Turn and response summary links carry their rendered address, source session, and source turn in native context. Their menu offers Send to a new session with the same labels before Send to a new session. The first action snapshots every source label from the extension record. The second action copies no labels. Both actions keep the source setup and recorded working directory. Compaction links retain Copy Path without source identity. HTTP and HTTPS links outside rendered Markdown tables keep the browser menu. Inside tables, they use Arc's native menu with Copy Link.

Selected response text offers the same two native menu actions in the same order. Both actions create an editable draft from the selected markdown, preserve source-turn navigation, and inherit the source setup and recorded working directory. Only the first action snapshots the source labels. A line opened without selected text offers neither action.

A turn card, a compaction card, a session heading, and a session list card offer New session with the same labels with or without source labels. It needs no selected text. On a finished turn card it hides while the selection offers the Send entries. Send to a new session with the same labels then starts the new session with the selected text. A compaction card, a session heading, and a session list card carry no selectable response text, so selection never hides it there. A changed-file row and a rendered link inside a card keep their own menus and never offer it. It creates an empty draft with the source setup, the recorded working directory, and a snapshot of every source label. A draft has no recorded working directory, so a draft source gives the new draft its own. The new draft carries no source turn. Its reader-started parent is the source session. The card carries body-style native context, so its folded headline and figures name the source session without hiding default Copy. The head suppresses default items, and descendant file and link contexts keep their own menus. A right-click on a turn card arms the same host record as one on a session heading, so the draft opens only in the panel that opened the menu. During `/clear`, the native command resolves its source through the panel that opened the menu. It copies that panel's successor until the successor render is painted. A source with no working directory or no current setup creates nothing and shows a message instead.

Session headings and session list cards share the triage, editing, session creation and details groups. Triage toggles come first. Entries that open an editor follow, titled with a trailing ellipsis. New session with the same labels comes next. Copy session ID and Show session details share the following group. A saved session heading adds Export session as HTML... in its final group. Inside a group, the most-used entry leads. Titles are short verb phrases that omit "this session".

The session heading's menu and the session list card's menu each carry pinning, the read state, archiving, Rename…, Edit labels…, New session with the same labels, Copy session ID, and Show session details, in that order. Copy session ID puts the row's exact session ID on the clipboard without opening Session details. Each entry reads the section its row names: the session list's three sections carry its read state and the heading's two sections carry its archived state. Rename… also reads the row's `sessionPersisted` value. The pin, read, and archive entries each show one direction, never both. The pin entries read the row's `sessionPinned` value to choose it. The heading's read entries read `sessionRead`, a word rather than a boolean so an entry offered on nothing markable is a key that is absent rather than one an editor's when clause reads the same as false. It is computed from the session's own turns and refreshed on every read change. The session list's read entries read its own section instead, and neither direction is offered on a row filed under the plain `arcRail` section, which names a session with no parsed turn to judge as read or unread. The session list's pin and archive entries also read `sessionArchived`, which the heading answers from its two sections instead. A pin, read, or archive command sends the named session and direction to the provider. The session list card's own hover controls send a pin or archive command the same way. The session heading's pin sends a pin command the same way with one press. It sets `aria-pressed` and draws in the notice tone while the session is pinned, and that tone is the heading's only pinned mark. Its accessible name stays the same in both states. An archived session's heading draws no pin. The heading's pin follows every route that changes the pin: its own press, the session list card's pin, `p` on a session list card, and the Pin and Unpin menu entries. The read state has no hover control of its own.

Three routes open the heading's menu: right-click on a session heading, `Shift+F10` on a focused heading, and a press on the always-visible three-dots button beside the heading. A session list card opens its session menu from a right-click or `Shift+F10` on the card itself. The heading's button exists because the first two heading routes both depend on a pointer gesture or a chord many Mac readers have no key for. The button holds no state. A press dispatches a synthetic `contextmenu` event on the button. The event bubbles to the `.sessionrow` used by the other heading routes. Every heading route opens the same native menu entries. `Show session details` is one of them, and it opens from a session list card even for a session the timeline is not showing. The dialog it opens resolves the row by session id from every session the panel knows, keeps its copy actions during redraws, and returns focus to the control that opened it when it closes. It closes safely when that session leaves the panel. The extension routes the selected command only to the panel that opened the native menu.

Every menu action has a keyboard route. Actions that change read, pin, or archive state update the shared extension state and repaint the affected surfaces together.

Copy-path actions use one spelling prepared by the extension. A file link embedded in rendered markdown receives the file menu only after its target has been resolved and checked inside an open workspace folder.

## Hosting the panel

The Arc tab is an editor tab backed by a webview panel. Its shared extension state lets another tab or a restored tab open on the same session. A tab restored with obsolete panel options is replaced in the same editor column.

The panel and the files it opens occupy different editor groups. Tests can verify the requested group but cannot verify what an existing VS Code window stored for an old tab. Changes to panel hosting need a manual check in the editor.

## Keyboard and screen-reader contract

Every visible action is keyboard reachable and has an accessible name that includes its visible information. Controls use native elements where the layout permits. Inline Prompt box skill marks use spans with the button role so they wrap with text. Disclosure controls carry `aria-expanded` and name what they open. A pressable control that needs a tooltip uses the panel hint, while read-only text and a row inside an open popover use a native `title`.

The Timeline landmark contains labelled session sections. Each visible session title contains its disclosure. Turn articles and compaction sections use their card heading as the accessible name. Turn body sections use visible subheadings. Headings wrap disclosure buttons and never become controls themselves.

The Sessions navigation landmark contains a heading that remains available when the visible title does not fit. Each group has a native heading and labelled list, with one list item per mounted session occurrence. Disclosure headings report total matches. Their `aria-controls` names the group list only while that list exists. Folded and empty groups omit that relation. Show more follows its group list as a separate native button. Group headings stick below the measured session list header. `#rail` remains the scroll owner.

Every session selector, sibling action, disclosure, saved-view menu, and Show more button keeps its native Tab stop. Tab and Shift+Tab cross the session list in document order. Up and Down supplement Tab by moving between disclosures, selectors, and Show more buttons. Home and End reach the first and last of those controls. Arrows from a sibling action start from its session selector. Movement never selects a session. Modified, prevented, composing, and editable-field keys retain their existing behavior.

From the first timeline stop, Shift+Tab reaches the separator, then the last session list control. Home returns to the first local navigation control without traversing rows. Repeated Shift+Tab presses move through the header controls to Search. Search narrows the list, and native Tab reaches the matching selector and its sibling actions. Enter or Space activates the focused native button.

The displayed session selector carries `aria-current="true"`, including each repeated group occurrence. Both densities retain the complete accessible name and full local activity timestamp. Figures and labels remain read-only parts of that selector. Clock updates change text without a live announcement.

Reconciliation preserves focus by session identity, group occurrence, and action. A removed occurrence returns to a surviving occurrence, then its disclosure, then a nearby selector, then a visible header control. Folding a focused group returns focus to its disclosure. A completed Show more press returns focus to its last newly drawn selector. Unrelated updates leave focus unchanged. Hiding the session list transfers focus from its controls or separator to visible compact navigation or the session view.

The focusable vertical separator controls the session list width. Left and Right move it by 10 CSS pixels. Home selects 160 pixels. End selects the viewport width minus the rendered separator width. Its accessible range and current value use those same bounds. Keyboard changes save the width immediately. Pointer changes save on release or cancellation. A smaller viewport caps the drawn width without replacing the saved preference. Space returning restores that preference. A deliberate resize updates it.

The timeline keeps one independent roving Tab stop. The navigation owner marks matching timeline controls with `data-roving` as subtrees arrive or change classes. It caches the complete walk and its visible members until the page changes. Controls outside that scope retain ordinary Tab stops. The owner ends its injected page observer on disposal.

An open popover rebuilds only when its own content changes. A shared parent fingerprint would rebuild it for unrelated updates. Replacing a focused native control closes its option list, even when focus is restored.

Disclosure state lives outside the card element. Card repainting preserves the card's open state, Activity filter, and prompt disclosure.

Activity owns command disclosures by step identity, including when an adjacent call groups a standalone step into a run. The log restores focus after retention removes its focused row. The timeline preserves that local choice while the same card survives.

Prompt recall starts when the caret is at the text field's beginning. Both arrow keys navigate while a recalled prompt is displayed. Recall announces its position in a separate live region because changing the focused field alone produces no screen-reader announcement.

A control that only exists at some panel widths is drawn as a control at those widths and as plain text everywhere else. The session heading's label chips file the session list under one label. Below the width the session list exists at, there is no list to file, so the chips are drawn as spans. A button that answers no press still takes a stop in the reading order and does nothing when it is pressed. The roving selector names the tag rather than the class for that reason. A chip that only reads keeps a native `title`, and the same chip as a button carries the panel hint instead.

A chip on a session list card cannot become a control. The card is itself one button, and HTML forbids a button inside a button. The session heading's own menu button is a sibling of its disclosure for the same reason: `.sessionheading` is a flex row holding the disclosure, the pin, the menu button, and the layout gear, in that order. The disclosure holds only the twist and the title. A press anywhere on it opens or shuts the session. Its panel hint gives the full session title first. The second line gives the full local time of the last activity, then the action on every shown turn. The pin, the menu button, and the gear sit outside it. The pin pins or unpins the session. The menu button answers its own press with the native menu. The gear opens the Timeline layout dialog. All three follow `.session` in the roving walk, in the order they are drawn. The heading draws no age, because the session list row and the newest card head draw it. An `.sr-only` span carries the full local time of the last activity, so the heading's accessible name keeps it.

The Activity head is a row. Its word controls disclosure, each message count is a filter button, and each tool-category count opens the shared raw-tool detail. These controls keep ordinary tab stops. Run and command controls share a separate roving tab stop inside the log, outside the timeline's walk.

A section head can carry a second action on a modifier key, with nothing on screen to say so. The Activity word opens or shuts the section on a plain press. A press with Shift held moves every visible message at once. The word's hint describes that second action. The panel names the hint's detail in `aria-describedby` while the word has focus. A hint can draw its title alone, and only an available detail receives that description link. A bulk press puts focus on the word.

The New session menu is a dialog of native buttons, and both of its triggers say so in `aria-haspopup`. Its list of pinned and recent setups keeps its own walk with one tab stop, outside the timeline's roving walk, like the label popover. Each list row holds an apply button, an Edit button and a pin button side by side. The stop starts on the first row's first button that can take focus, and it follows focus inside the list. Tab enters the list from the "Same setup as current" row and leaves it for the Agent field. Up and Down move to the same kind of button in the next or previous row and wrap at the ends. Home and End move to the first and last row. A row without that kind of button takes focus on its pin. Left and Right move across one row's buttons and stop at its ends. An unavailable pinned row's apply button is disabled, so the walk lands on its Edit or its pin. A refresh that disables the stop's apply button moves the stop to that row's pin. A refresh that removes the stop's row moves the stop to the same button in the next row, else the previous row. Focus never stays on a disabled button. Opening the menu focuses the "Same setup as current" row, else the list's stop, else the Agent field. Edit, and an opening that asks for a custom setup, focus the Agent field. After a pin press, focus moves to the new pinned row's pin once a refreshed list shows a new pinned setup with those values. After an unpin press, focus moves to the next row's pin once the pinned setup is gone, else to the previous row's pin. A refresh that shows neither result leaves focus on the pressed pin, or on its nearest remaining neighbor when that row is gone. Moving focus off the pressed pin before the result arrives cancels the move, so the result moves focus nowhere. Agent, Model, Effort and Permissions use the shared select-only combobox. Each field has one Tab stop, and its options never receive DOM focus. Arrow keys open the list and move its tentative selection without wrapping. Home and End reach the boundaries, and Page Up and Page Down move by ten choices. Printable keys search option names. Enter, Space, Alt+Up, Tab or leaving the field accepts the tentative choice. Tab retains normal browser focus movement. Escape or pressing the expanded trigger cancels it. Pointer hover changes only the visual treatment. Pressing an option accepts that option. A refresh that disables the focused field moves focus to the next enabled visible control. Model and Effort mark the applied CLI defaults when known. Loading and unavailable metadata remain field statuses. The field pin keeps focus after a press, and its pressed state follows each refreshed list. A hint open on Edit or a pin takes the first Escape, and the next Escape closes the menu.

An agent request draws one question at a time, behind a real tab strip. The strip holds one tab stop of its own, and it is not part of the panel's roving walk. Its tabs, and the request's fold, sit before the request's actions in the page, so the query that moves focus to the next request after one resolves excludes both. Three polite regions stay apart: an arriving request, the move to the next question, and the sentence beside Send. A region that mixed two subjects would read as one.

Keyboard operation is part of the component contract. Mouse-only behavior does not ship. Visible focus and readable words carry meaning. Glyphs and color do not carry meaning alone.
