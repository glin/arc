# Session discovery and relationships

## Session discovery

`allSessions` merges Claude transcripts and Codex rollouts into a chronological list. Each `SessionFile` carries its source agent, recorded cwd when readable, stable id, activity time, and metadata for deciding open-project membership.

The recorded cwd decides membership. The open folders belong immediately. Git supplies the worktrees registered with their repositories in the background, after which their directory trees belong too. A worktree inside an open folder already belongs through that folder, so registration admits only worktrees outside every open folder. Claude's directory slug can collide across paths, and Codex directories are organized by start date rather than project. Discovery can use a directory name to avoid unnecessary reads. When the record supplies a cwd, the name alone cannot establish membership. A transcript without a readable cwd keeps the exact-folder fallback only for an open folder, never for an added worktree root.

The first listing waits for Git's answer before it changes reader state. Later topology reads keep each open folder's last successful roots through a temporary failure and invalidate the catalog when those roots move. Git worktree registration is the available proof of the relationship. After a worktree and its registration are both removed, an old transcript cwd cannot establish which repository owned it.

Prompt delivery, compaction, response-link handoff, and selected-text handoff use the discovered session's recorded cwd. New sessions started from the ordinary launcher continue to use the editor's open folder.

Listing and parsing are separate work. Listing admits Claude transcripts with a typed human prompt and Codex rollouts in the repository scope. The progressive worker reads selected sessions into turns. Persisted bounded turn starts and metadata supply unread, status, and context facts independently from selection. Completed primary spend sources supply the newest start and outcome when the bounded read cannot reach them. Session list and open-heading cost come from the incremental spend index because a tail cannot establish a whole-session total. Pins control session list placement alone.

Refresh admission shares read and filesystem-check allowances across Claude sources and yields between batches. Admission completes before catalog publication. Cancelled and superseded scans retain complete lines and unfinished UTF-8 bytes. Compatible appends preserve scan progress and confirmed human evidence. Without confirmed human evidence, unscanned appended bytes retain unknown membership until admission resumes. Changed physical identity, shrinkage, or a changed same-size revision restarts admission. Unavailable evidence retains unknown membership.

Sessions started as child-agent work remain available but are folded away from the ordinary list unless the reader pins or selects them. Classification must not hide a session that edited workspace files or whose opening turn is still active.

A typed command that the CLI answers by itself supplies no admission evidence, even when model work follows its answer. Model work after a manual compaction makes `/compact` admission evidence again. A transcript containing only such commands stays off the session list. Fallback naming uses command withdrawal evidence from the first 128 KiB. A withdrawn command gives way to the next typed or reader-queued prompt. Whole-file metadata reads can name prompts beyond that window. A command without a recorded CLI answer remains eligible. Catalog refreshes recheck pending command admission and preserve reader-owned state when a session leaves and returns.

## Transcript interpretation

A Codex child rollout can begin with a replay of its parent's records. The replay gives each envelope a new write time but keeps the original turn clock and parent session identity. Codex readers compare those facts with the child rollout's opening record so inherited turns do not become new cards, turns, or billed requests. The child's own requests still roll up to the parent session.

A session belongs to the current window when its recorded cwd is inside an open workspace folder. It also belongs when that cwd is inside a worktree registered with the folder's repository. Git supplies worktree roots asynchronously. A directory name remains only a hint because slug and path-prefix collisions make directory-only membership unsafe. Continuing a discovered session uses its recorded cwd. A queued submission waits when its session leaves this scope. It resumes if the workspace returns. Pending session rows follow the same scope. Workspace changes revoke the old scope even while every panel is closed.

A fresh `codex exec --json` command links from one top-level `thread.started` event in its paired stdout. Both parent agents reject resumes, quoted or nested events, ambiguous starts, mixed opted-in launches, and stderr-only evidence. A Claude Bash result can identify a dispatched session when its recorded command invokes Claude or passes `--arc-dispatch` as a standalone wrapper argument. Direct Claude launches supply a background line or foreground JSON result. A Claude command that resumes or continues a session with `--resume`, `-r`, `--continue` or `-c` dispatches nothing, because its result names the resumed session. The whole Bash call then dispatches nothing, even when it also starts a fresh session, because the reader cannot tell which launch printed a result. The same command with `--fork-session` runs in a new session, so it dispatches that one. The reader stops parsing Claude command arguments at a heredoc body or PowerShell here-string. A prompt passed on standard input never reads as a flag. A heredoc inside a double-quoted command substitution, as in `"$(cat <<'EOF' ... EOF)"`, stays inside that one argument, even when its body holds a double quote. An opted-in wrapper supplies one exact `ARC_DISPATCH_SESSION` JSON line in its paired result for each session it starts. A command that chains opted-in launches links each session its receipts name. An opted-in launch beside a direct Claude launch links nothing. The line carries `"owned":true` when the reader asked for the session, and any other value of `owned` rejects the receipt. A direct launch is never owned. A wrapper can relay another command's receipts. The reader rejects every receipt when a result contains a malformed or oversized receipt, or more receipts than its command has opted-in launches. It also rejects a result whose receipts pass a small fixed limit, whatever its launch count. It rejects Claude receipt IDs that share their first eight characters. It rejects repeated full Codex IDs. Different agents keep separate identities. It rejects matching output from another command. A short id resolves only when one existing catalog Claude session in the current project has that prefix. The derived session cache keeps the parent-owned edge. A changed parser generation rebuilds unchanged positive and negative entries and incompatible Codex cursors. One parent file links children, subagents, and dispatched sessions up to the derived session cache's per-file reference limit. Links follow the file's first occurrence of each reference. The cache retains a deterministic bounded subset of parents, and a parent that grows keeps the children it already linked. The parent turn retains launch call ids beyond its bounded Activity steps, so a long turn keeps its dispatched rows.

## Parsing and attribution constraints

- Claude child discovery scans parent transcripts in the cancellable worker. The derived cache keeps complete parent-reference facts and separate pending checkpoints across host restarts. Each reuse validates the normalized source path, parser generation, file identity, size, modification time, current catalog membership, and child working directory. An append resumes a fixed byte target with retained launches and record fragments. Detected replacement, shrinkage, or changed evidence rebuilds that source. A deleted or replaced child fails its own stat and repository-scope check. The verified parent and child path remains available for parent-card spend. Navigation also requires the child working directory to belong to the open repository or a registered worktree.

## Relationship discovery contracts

`dispatchreceipts.ts` exposes read-only standalone relationship scans. Each iterator starts a fresh evidence epoch and visits retained launches without a total count cutoff. Each generator resume grants the next filesystem operation its remaining entry, byte, or check allowance. Partial receipt buffers, source digest positions, and the directory cursor survive between grants. Cancellation and iterator closure release retained descriptors. Admission requires committed receipt and binding witnesses plus the producer's durable startup opening for either provider. Directory identity survives sibling writes. A changing native source stays pending until a later scan validates a stable revision. Evidence revisions and scoped endpoints are checked again before publication. Receipt references retain reader ownership and empty tool IDs. Unexpected filesystem failures yield refusal status alongside existing charges. Status identifies the failed launch or whether receipt storage opened. Missing paths, rejected evidence, changing sources, and cancellation retain their existing outcomes. Consumers that ignore status retain best-effort references. Relationship scans supply no delivery authority or billing evidence.

The `admittedDispatchReferences` helper in `turnrail.ts` applies the same parent conflict and duplicate ownership policy as headings. The progressive worker retains receipt references and refusal flags across refresh generations within one discovery epoch. It grants each step the request's remaining bytes and charges the returned work before interpreting status. Cancellation and epoch replacement close the scan. Response generations still control host publication. Transcript and receipt claims reach shared admission together. Raw competing claims remain available to host parent indexing. A refused launch or interrupted receipt directory holds new dispatch publication when a qualified receipt or resolved transcript dispatch exists. The worker returns its existing pending checkpoint and closes the iterator. The next ordinary discovery request starts a fresh receipt scan within the retained epoch. Initial unopened storage without qualified receipts preserves transcript fallback. A scan without qualified receipts or resolved dispatches preserves native discovery. Refusal errors enter neither checkpoints nor replies.

Synchronous and cooperative session-cost reads first discover the selected source tree. Source-only reads skip catalogs and receipts. Provider catalogs retain their first unexpected refusal without changing ordinary transcript discovery. Receipt scans include provider catalog metadata and selected native descendants. A qualified receipt touching the selected tree requires complete catalogs and receipt competition before native census. An unresolved requester requires native-child enumeration before repeating receipt qualification. A touching receipt then requires competing catalog bodies to reach their captured end before descendant admission. Empty Claude bodies require an explicit zero-size check. Verified pathname disappearance preserves availability. `ENOENT` and `ENOTDIR` establish absence at permitted boundaries. Other filesystem failures refuse affected admission. Codex catalog enumeration classifies each uncertain pathname, and undefined openings require a pathname check. Bounded null openings establish no admitted identity. Codex body checks compare cursor offset with the captured target without changing framing or pending-ownership policy.

A dispatch-bearing cost tree also refuses unknown receipt competition without a qualified touch. A catalog refusal requires an unresolved requester in that case. Native descendants and linked print usage alone do not make a tree dispatch-bearing. Missing or non-directory receipt storage preserves the ordinary source tree. Initial unopened storage without qualified receipts also preserves that fallback. Later storage failure cannot clear an earlier applicable receipt. Known unrelated endpoints require no unrelated body scans or native-child enumeration. Applicable receipts repeat receipt validation and the selected traversal. Both routes retain native child precedence and canonical source deduplication. Duplicate references combine native tool IDs and reject competing source paths. Catalogs and captured bodies do not establish an atomic filesystem snapshot. Appends beyond a captured Codex target enter a later observation. Total work has no aggregate bound. Cold work scales with retained directory entries, validation bytes, and scoped catalog entries per qualifying launch. Retained reader state holds one receipt buffer, one source digest, and the current launch's evidence paths.

`sessioncoverage.ts` decides whether a source is present, absent, or unknown under one domain, repository scope, and accepted revision. Physical enumeration and admitted membership carry separate evidence. Enumeration covers visited directories within each provider's supported depth. Unvisited child directories retain unknown absence until separate evidence qualifies them. Unread directories, failed candidates, and unavailable admission retain unknown membership. A missing provider root establishes an empty physical enumeration. Published rows supply no absence proof. Known same-ID collisions revoke recorded-source delivery before catalog publication. Collision paths use bounded opening reads whose descriptor and pathname revisions agree. Scope and coverage revision bind each observation. Qualified recovery replaces affected positive opening metadata and invalidates the affected held Codex stat. Qualified hidden Codex openings reserve physical competition independently of displayed membership. Hidden same-ID sources and hidden changed IDs that collide with visible sources retain quarantine. Cached metadata alone cannot resolve replacement, scope exclusion, or the surviving identity. Hosted Stop and question answers retain their process callbacks. The host retains omitted accepted sources during incomplete enumeration and blocks their source-bound delivery through prompt recovery. Proven absence removes derived caches, history, navigation, and exit evidence. Drafts, queued submissions, aliases, comments, and pending recovery remain recoverable. Deferred compaction waits for unknown membership and cancels on proven absence. The physical Claude child census reserves identities across each native subagent directory, including unreferenced descendants. Unqualified openings retain competition without establishing scope exclusion. Relationship discovery still completes before the host accepts new session membership.

The host publishes scoped catalog identities with discovery coverage, scope, and revision to session query consumers. Live filters, saved views, and content search resolve prefixes before narrowing their pools. Discovery admission suspends prefixes until accepted catalog metadata establishes completion. The shared shell receipt lexer reads balanced bare parenthesized arguments as opaque words and computes their boundaries once per command segment. Prefixed expressions keep their existing command boundary. Expression contents cannot supply the outer launch's opt-in. Launch discovery masks comments and PowerShell escaped parentheses before reading command boundaries. Bash parameter expansions, brace words, and continued words keep literal hashes. Bash backtick delimiters bound inner comments and heredoc traversal before outer launch discovery. Arithmetic grouping keeps its enclosing arithmetic frame. Parameter defaults and conditional operands mask literal text while nested substitutions read their own script. Bash recognizes conditional patterns after unquoted brace openers, negation, and timing prefixes. Timing prefixes include `time`, `time -p`, `time --`, and `time -p --`. Argument continuation rejects ambiguous backtick quotes and preserves Bash quote boundaries. Other shell readers retain their shared quote masking. Claude receipt readers accept Bash tools and use their declared Bash grammar. Codex completed `CommandExecution` records also supply shell receipts. Their recorded Bash, PowerShell, or pwsh invocation establishes grammar only when its script matches the selected command text. This includes complete and visited-EOF Codex entries whose parent files no longer grow. Derived title and Codex opening generations remain independent.

Relationship discovery freezes source targets and retains acknowledged reducer state in the host's derived cache. The host retains the frozen epoch header and spend-source snapshot. Each charged quantum of either provider sends its source entry, scheduler state, and completion changes. Zero-byte changes enter the next acknowledgment or final checkpoint. The first acknowledgment supplies a missing epoch header. Later acknowledgments reuse it without copying the catalog or cumulative completion list. A new epoch starts with every unchanged finished source complete. Restored completions require current-worker admission when their sources become reachable. A source completed in the held epoch keeps its captured cut. Relationship admission leaves completed sources unchanged until the next epoch. Later writes enter normal refresh after publication. Finished sources require matching parser, session, classification, identity, revision, and accepted evidence, with no pending comparison. Their consumed offset equals the current size. Claude sources retain incomplete trailing fragments for later appends. Codex sources finish at qualified EOF even when terminal framing leaves their own completeness false. Eviction retains the small evidence header and finished flags while dropping heavy cursor state. Unchanged finished sources then require no relationship reads. Changed evicted sources rebuild from byte zero. The host assembles restart checkpoints through completion additions and removals. Scope, parser, epoch, source generation, and sequence identify compatible progress. Pending answers carry no catalog rows or figures. A pending Claude source withholds the complete reply for every session. Scanned Codex sources permit complete replies while pending validation or parsing, with their own completeness flags false and continuation work requested. Each epoch retains scoped child metadata and resolves ownership collisions on every recursive walk. Changed unfinished sources invalidate their child metadata. The worker rebuilds recursive reachability from qualified references before publishing a complete replacement. Dispatched enrichment retries preserve valid ownership and mark retained spend partial.

Panel relationship cursor limits are soft. One protected Claude source retains oversized records and unmatched launches across quanta, cache pressure, and restarts. A protected child keeps parsing priority while pending parent validation hides its ownership edge. Protection ends when the child is missing, completes, or reaches its qualified parsing target. Finished evidence headers remain above the soft allowance when necessary for unchanged reuse. JSON parsing of one oversized record cannot yield. A Codex scan that skips an oversized record retains incomplete coverage through later appends and EOF. The shared relationship parser generation invalidates cached coverage from earlier framing rules.

Both relationship scanners retain SHA-256 chain evidence over 4 KiB blocks and one unfinished tail from the bytes supplied to parsing. Changed source stamps require resumable comparison of the entire consumed prefix before append parsing resumes. Stamps include exact modification and change times, physical identity, and byte size. Bounded scans check descriptor and path stamps at reader creation, after each read, and before acceptance. Unknown validity clears current completeness while older display facts retain their accepted revision. Complete replies publish compatible pending Codex sources' retained dispatch references and their dispatched figures, including sources beyond the request allowance. These references include dispatches parsed from newly appended bytes, minus retracted dispatches, while the source entry remains incomplete. Dispatch references add no recursive ownership edge. Mismatches, replacement, truncation, and incompatible terminal extensions retire dependent facts and advance the source generation. A mismatch ends the attempt without an immediate retry.

Claude relationship quanta receive at most 1 MiB, and Codex quanta receive the remaining request allowance. Both providers share a 16 KiB reserve, a 256 KiB read ceiling, and a 15 ms cooperative slice. A slice makes its first validation, replay, or parsing read even when it starts past its deadline, so every slice advances. The one-byte read that checks what follows a terminal record does not count as that read. Validation consumes the provider allowance minus the reserve. Validation reads block-aligned buffers and checks the deadline between hash blocks. Unhashed bytes from an expired slice are charged and reread on resume. Every returned byte, including replay and abandoned reads, enters the request meter. Additional serialized evidence is limited to 16 KiB per source and enters the existing cursor allowance. Discovery admits one active request and one latest waiter. Cancelling active discovery preserves an unaborted waiter. Each request permits eight quanta that read bytes or reach the deadline, within 8 MiB, and sends at most ten replies. Admission shares one parent stat between its reachability walk and source checks. Publication checks unfinished sources separately. Selected reads remain independent. Worker scans yield between validation, replay, and parsing reads. Synchronous unbounded Codex session-cost scans read through the size captured at opening despite subsequent growth.

A changed revision requires O(consumed prefix) validation reads. A changed large source needs multiple requests before it qualifies. Hash chaining bounds retained evidence, and chunking bounds individual reads. Neither bounds total validation work. Source stamps and collision-resistant evidence establish observed agreement, not an atomic filesystem snapshot. Metadata-preserving concurrent rewrites can evade these checks or produce mixed observations. An unreached same-size Codex rewrite retains dispatch references with an incomplete entry until comparison runs. Continuous rewriting or faster appends than validation can prevent qualification. Stable input permits eventual completion when scheduling and parser limits allow it. Synchronous reads, record parsing, cursor copying, and serialization have no hard latency bound.
