# Discovering sessions

[Session history](session-history.md) owns selected reads, metadata recovery, and cache migration. [Accepted catalog reads](window-channel.md#accepted-catalog-reads) owns channel qualification and delivery authority.

## Session discovery

[`allSessions`](../extension/src/panelhost.ts) owns catalog assembly. Membership remains separate from selected-turn parsing. Bounded metadata, turn starts, and completed primary spend sources supply session facts independently of selection. The incremental spend index supplies lifetime cost.

The Codex walk lists a file whose name ends in `.jsonl` as a rollout. It lists a file whose name ends in `-<thread id>.jsonl.zst` as a compressed rollout, without a stat. Both suffix tests are case-sensitive on every platform, so a name that ends in `.JSONL.ZST` is neither. A compressed rollout gives no row and gets no opening read. The host keeps the compressed rollouts in its set `compressedRollouts`. Each walk adds the names it lists, and a complete walk also removes every name it no longer lists. A watcher event for a compressed name starts no refresh. The host adds that name when it takes the next wake batch.

Claude admission requires an eligible typed human prompt. A command answered locally by the CLI supplies no evidence, even when model work follows. Model work after manual compaction makes `/compact` eligible again. A command without a recorded CLI answer remains eligible. Refresh rechecks pending command evidence and preserves reader state when admission changes.

Admission shares read and filesystem-check allowances across Claude sources and yields between batches. It completes before catalog publication. Cancellation retains complete lines and unfinished UTF-8 bytes. Compatible appends preserve progress and confirmed human evidence. Unscanned appended bytes remain unknown without that evidence. Replacement, shrinkage, or changed same-size revisions restart admission. Unavailable evidence remains unknown.

After a catalog is accepted, the published rows stay that catalog's sessions while relationship discovery continues. A refresh can list an accepted source again with the same device and inode and no smaller size. That source takes the listed revision, so its metadata follows the file. A walked source of a session that this panel started and still awaits joins them. That source must be the only walked source of its session ID and a walk member without a collision. It must also have a supported file identity, lie inside repository scope, and be absent from the accepted rows. Child transcripts wait for discovery, and discovery stays incomplete.

Agent runs remain discoverable but fold away unless pinned or selected. Classification must preserve visibility for sessions that edit workspace files or whose opening turn remains active. Unknown classification matches neither polarity of an agent-run predicate. A dispatched Codex session without a reader-owned launch has unknown classification until its person scan reaches the end of its file. Malformed small transcripts remain unknown. Complete records before an unfinished final fragment still supply classification evidence.

## Repository scope

Repository scope includes recorded working directories inside open folders or registered worktrees of those folders' repositories. Claude directory slugs and Codex date directories supply hints, not membership. Without a readable Claude working directory, only an exact open-folder fallback applies. Added worktree roots receive no fallback.

[`RepositoryScope`](../extension/src/repositoryscope.ts) owns Git worktree reads. The first listing waits for scope before changing reader state. Failed initial reads use open folders. Later failures retain prior roots, because temporary Git failures must not remove sessions or reader state.

Scope reads ask Git again after 15 seconds. Removals require a second answer after 5 seconds, because Git can briefly omit registered worktrees. Failed answers preserve held removals. Confirmation retries at 5 seconds stop after three failures and return to the regular interval.

Open folders always remain. Removal confirmation uses unfiltered per-folder answers, including nested roots hidden by published roots. Nested-only changes move no scope revision and cancel no selection.

Registered checkout identities remain independent of discovery roots. Identity-only changes refresh headings without moving discovery revision or cancelling selection. [`startingWorktree`](../extension/src/repositoryscope.ts) owns heading worktree selection.

Containment requires a path boundary. Windows drive paths compare without case on every host. Other paths ignore case on Windows and retain case on macOS and Linux. Removed worktree registration and a removed worktree leave an old working directory without repository evidence.

Continuing a session, compacting it, and handing off responses or selected text use its recorded working directory. The ordinary New launcher uses the editor's open folder. Queued submissions and pending rows wait outside scope and resume when scope returns. Workspace changes revoke scope even with every panel closed.

## Relationship discovery contracts

Keep physical presence, admitted membership, scope, and accepted revision separate. `sessionPresence` answers present, absent, or unknown only within the matching domain, scope, and revision. A prompt box Send during a scope walk is the one exception, which [Delivery and recovery contracts](prompt-delivery.md#delivery-and-recovery-contracts) defines. Physical coverage reaches visited directories within the provider's supported depth. Unvisited directories, failed candidates, and unread admission remain unknown. A missing provider root establishes empty enumeration. Published rows supply no absence proof.

Same-ID collisions revoke recorded-source delivery before publication. Competing sources remain quarantined through incomplete walks until qualified openings or relevant pathname absence resolve them. Descriptor and pathname revisions must agree. Hidden Codex openings reserve competition independently of displayed membership, including changed IDs that collide with visible sources. Cached metadata alone cannot establish replacement or scope exclusion.

Incomplete enumeration retains omitted accepted sources and blocks their source-bound delivery through prompt recovery. Proven absence removes derived history, navigation, caches, and exit evidence. Drafts, queued submissions, aliases, comments, and pending recovery remain recoverable. Deferred compaction waits on unknown membership and cancels on proven absence. Hosted Stop and question answers retain their process callbacks.

Claude discovery scans parent transcripts in the cancellable worker. Reuse requires matching normalized path, parser generation, physical identity, size, modification time, catalog membership, and child working directory. Appends resume a captured byte target with record fragments and unmatched launches. Replacement, shrinkage, or changed evidence rebuilds the source. Each child receives its own stat and scope check. Verified parent-child paths remain usable for spend even when navigation excludes the child.

Native child census also reserves unreferenced Claude descendants. Codex child replays retain parent identity and original turn clocks despite new envelope times. Readers exclude inherited cards, turns, and requests. Actual child requests remain attributable to the parent. [Card sources](timeline.md#card-sources) owns opening and interactive-resume classification.

### Dispatch evidence

A fresh `codex exec --json` launch requires exactly one top-level `thread.started` event in its paired stdout. Resumes, nested or quoted events, ambiguous starts, mixed opted-in launches, and stderr-only evidence establish no link. Direct Claude launches require their paired background line or foreground JSON result. Claude `--resume`, `-r`, `--continue`, and `-c` reject the entire Bash call unless `--fork-session` establishes a new session.

Wrappers opt in with standalone `--arc-dispatch` and return exact `ARC_DISPATCH_SESSION` JSON lines. Chained opted-in launches link their named sessions. Mixing a wrapper with direct Claude launch rejects every link. `owned` is absent or `true`. Only `true` establishes reader ownership. Direct launches remain unowned.

Malformed receipts, lines over 4096 characters, excess launch receipts, or more than 16 receipts reject the entire result. Claude IDs sharing eight leading characters conflict. Repeated full Codex IDs conflict. Providers retain separate identities. A Claude prefix resolves only against one existing scoped catalog session. Output from another command supplies no evidence.

The shared lexer excludes prompt bodies, heredocs, here-strings, comments, quoted expressions, and opaque grouped arguments from launch flags. Codex command grammar requires a matching recorded shell invocation. Unknown grammar admits only launches whose kind and position agree under Bash and PowerShell. Extglob-dependent Bash syntax supplies no receipt ownership. `claudeLaunchKind`, `commandWords`, and `maskQuoted` in `transcript.ts` own the grammar rules.

`DispatchReceipts.relationships` reads durable standalone evidence without granting billing or delivery authority. It requires committed receipt and binding witnesses plus durable provider startup evidence. Each iterator starts a fresh evidence epoch. The final step of each launch names the launch. It also names the requester and dispatched session once the read reaches the catalog lookup. Grants bound the next entries, bytes, and checks while retaining partial buffers, digests, and directory position. Cancellation closes descriptors. Unexpected filesystem failures return refusal status with charges.

Transcript and receipt claims reach shared conflict admission together. Worker receipt state survives refresh generations, cancelled discovery requests, and repository root changes within its discovery epoch. A cancelled discovery request leaves the worker running, and the next request resumes the receipt scan where it stopped. When the identity of the store directory changes before the scan publishes, the next request starts the scan again from its first entry. A new worker also starts the scan from its first entry. A root change cancels the discovery request of a catalog refresh, but [refresh scheduling](session-history.md#saved-state-and-refresh) keeps a running discovery continuation. After a root change, the scan reads again each visited launch whose requester or dispatched session changed catalog rows. It skips a launch whose read stopped before the catalog lookup. It drops the earlier link of each such launch. Refusal holds new dispatch publication when qualified receipts or resolved transcript dispatches exist. The next ordinary request starts a fresh receipt scan. Initially unopened storage without qualified receipts preserves transcript fallback. No qualified receipts or resolved dispatches preserves native discovery.

Session-cost reads first discover the selected native tree. Source-only reads skip catalogs and receipts. A qualified touching receipt requires complete catalogs, receipt competition, and captured competing bodies before descendant admission. An unresolved requester first requires native-child enumeration and repeated qualification. Empty Claude bodies require an explicit zero-size check. Bounded null openings establish no admitted identity. `ENOENT` and `ENOTDIR` establish absence only at permitted boundaries. Other filesystem failures refuse affected admission.

A dispatch-bearing tree also refuses unknown receipt competition without a qualified touch. Catalog refusal then requires an unresolved requester. Native descendants and linked print usage alone do not make a tree dispatch-bearing. Missing or non-directory storage preserves native fallback. Later failures cannot erase an earlier applicable receipt. Unrelated endpoints require no unrelated body scans. Native children take precedence. Canonical deduplication combines tool IDs and rejects competing paths.

### Progress and limits

Each parent retains its first 4096 references. The derived cache retains a deterministic subset of at most 10,000 parent files. A Claude child's row also keeps the working directory that the child's head names, with the size, modification time and physical identity of that read. A new worker resolves the working directory of an unchanged child from that row with one stat and no read. A child without a row reads its head again in each new worker. A dispatched session's row also keeps that session's settled spend facts, with the file revision and spend tree they were read at, under a facts version of their own. A new worker reuses the facts of an unchanged session without a read. A session whose revision or tree moved reads its spend again. The facts of a Claude session also record whether the repeated-record map covered its file when the worker read the session's activity. A bounded activity read without a covering map omits the records that the map does not classify yet, so the answer can call a finished session unfinished. When a map later covers the file, facts read without one read only their activity again and keep their spend. Facts read with a covering map stay as they are. The derived cache keeps the smallest saved facts up to 16 MiB in total. A dispatched session without a row reads its spend again in each new worker. Appends preserve existing links. Launch call IDs survive the Activity step bound. Relationship generation changes invalidate both providers, including unchanged positive and negative entries. Metadata and Codex opening generations remain independent.

Discovery freezes source targets within an epoch. A repository root change continues the epoch. Sources under both root sets keep their rows and captured cuts. Added parents join the epoch, and removed parents leave its completions. A child that returns without its reference entry checks its completion again when the walk reaches it. Child resolutions that found no child, or a child outside the new roots, resolve again. Charged quanta acknowledge source progress and completion changes. Restart admission rechecks saved completions. Finished sources keep their captured cuts until the next epoch. Unfinished Claude sources withhold complete catalog replies. Codex sources permit complete replies with their own coverage false and continuation requested. Cursor retention uses a soft 64 MiB allowance. It preserves one protected Claude source, oversized fragments, unmatched launches, and finished evidence headers. Partial replies alone release no worker memory. Skipped oversized Codex records keep coverage incomplete through later appends and EOF.

Both scanners retain SHA-256 chain evidence over 4 KiB blocks and one tail, plus an anchor: the chain before the final full block. When a file grows, the reader hashes the final full block and the tail from the anchor, and checks the marks that the evidence keeps. A match at all of them accepts the consumed prefix, and parsing resumes at the new bytes. A check that ends short, unstable or pending retries in the next quantum. A same-size change compares the entire consumed prefix. The comparison accepts only a read that saw no growth. Growth during it leaves it pending, and the next quantum restarts it over the entire consumed prefix. Evidence without an anchor or with a mismatched anchor also compares the entire consumed prefix before append parsing resumes. Stamps include exact modification and change times, physical identity, and size. Readers check descriptor and pathname stamps at opening, after reads, and before acceptance. Every read stops at the size the reader saw at opening. A forward read or a mark check stays stable when each later stamp keeps the physical identity and shows a size above the opening size. The stamp cannot tell an append from a rewrite that also grows the file, so such a read can return bytes from before a rewrite. When a check sees a grown stamp that it did not see before, the reader marks the evidence at the end of the reads so far. Growth before the first read makes no mark, because evidence at offset 0 holds no bytes to check. A mark keeps its offset, the chain before its final full block, and a hash of the chain through that block and the tail. Before the read qualifies, the reader runs check passes. A pass checks the stamps, then hashes the final full block and the tail at each mark again. When a check in a pass sees a new grown stamp, the reader marks the end of the evidence and starts another pass. The read qualifies after a pass that sees no new grown stamp. A mismatch makes the read unstable, and the next quantum compares the entire consumed prefix. A new grown stamp in each of four passes leaves the read unqualified. So do cancellation in a later pass and a mark without the bytes for its check. The evidence keeps the marks of the read, at most eight, whether or not the read qualified. Past eight, a new mark replaces the latest one. The next scan of the grown file runs the same check passes, first over the kept marks in offset order and then over the anchor, so an allowance can end before the anchor. The evidence keeps every mark until a scan accepts the prefix, a check mismatches, or the scan falls back to a whole-prefix comparison. A scan that starts again from the beginning also removes every mark. A shrink below the consumed prefix or the last accepted size, a changed identity, or a byte after an applied final record that is not a line end starts it. When that scan stops before the anchor with the read pending, the evidence also keeps the stamp of its checks and a position. The position is the first mark after the longest run of checks in any pass of the scan that matched without a new grown stamp. Every pass of the scan after it starts at that mark when the file keeps that stamp or grew from it with the same physical identity. After the anchor, each such pass checks the earlier marks again until the slice deadline, cancellation, a mark without the bytes for its check, or a new grown stamp, and then accepts the prefix. Otherwise the scan starts at the first kept mark. An unstable stamp or a short check keeps no position. Any other stamp change makes the read unstable. Unknown validity clears completeness while accepted display facts retain their revision. Compatible pending Codex entries retain updated dispatch references and figures with incomplete coverage. Dispatch references establish no recursive ownership edge. Mismatch advances source generation and ends the attempt without immediate retry.

Claude quanta receive at most 1 MiB. Codex receives remaining request bytes. Both use a 16 KiB reserve, 256 KiB read ceiling, and 15 ms cooperative slice. The receipt scan has its own allowance in each request: 4,096 steps or 250 ms, whichever ends first, within the request's remaining bytes. Each step is one filesystem operation. After each step the scan yields to the worker's other messages, so a window read runs between steps. The scan makes its first step even past the deadline. Forward reads also leave the bytes for four passes of mark checks. Check passes ignore the slice deadline until they check earlier marks again after the anchor. The first pass also ignores cancellation until then. Each slice makes its first advancing read even past deadline. Every returned byte counts, including validation, replay, and abandoned reads. Serialized evidence receives at most 16 KiB per source within cursor accounting. Requests permit eight charged quanta within 8 MiB and at most ten replies. Discovery admits one active request and one latest waiter. Selected reads remain independent. Each request gives Codex dispatched spend its own 8 MiB and 15 ms budget. That time counts only spend reading, so reads for other dispatched sessions in the request leave it intact. Each Codex dispatched root keeps its own spend aggregate across requests, with its traversal and its unfinished file parse, so no root delays another. The worker drops the aggregate of a root that started a new turn. A root that finds the request's spend budget spent reads nothing in that request and keeps its aggregate.

A complete reply carries `membershipSettled` when no catalog member or relationship asks for another pass. A reply that asks for another pass only for dispatched spend or person facts still publishes its catalog. Listing coverage, the query context and the completion stamp then follow that catalog. The dispatched facts it carries stay partial or unfinished. Each later pass sends a spend-only request. That request reads the spend and person facts of the dispatch references of the last complete reply. It starts no epoch, walk or receipt scan. It passes over a settled root whose file keeps its revision, so it reads only the roots whose spend is pending or whose file moved. A full pass still checks the spend tree of every root, so a descendant that grows under an unchanged root waits for the next full pass. A spend-only reply also returns the saved facts that the pass settled, and the host saves them with the reference rows. A catalog refresh follows a spend-only reply only when a drawn dispatched figure moved. While members stay settled, a catalog refresh that reuses the held catalog and finds a dispatched file moved sends a spend-only request, not a full pass. A worker that holds no complete reply for the requested roots answers `held: false`. That reply, or a failed spend-only request, sends discovery back to a full pass.

Same-size changes require O(consumed prefix) validation. A file that grows and is rewritten keeps its accepted facts when the rewrite changes no byte in any checked block. The checked blocks are the final full block and the tail at the anchor and at each kept mark. The reader checks them in the check passes of a read and again when the next scan finds the file grown. Such a file keeps its old facts until a same-size change, a shrink, a replacement, or a mismatch at a later check. The reader does not check a mark again after a later mark replaced it. A source whose kept marks need more bytes than one allowance completes over several scans. Growth between scans or during a scan never moves the position back. A scan of a file that only grows moves the position past at least one mark, or accepts the prefix, when two conditions hold. No new grown stamp appears from its opening through its first mark check, and its allowance covers that check. So at most eight kept marks and the anchor need at most nine such scans, with any number of other scans between them. Growth before the end of the first mark check in each of the four passes of every scan can keep such a source unfinished. Growth during the anchor check of each of the four passes leaves a scan pending at any read speed. The anchor check is the last check before a resumed pass checks earlier marks again. For a scan that checks only an 8 KiB anchor from the page cache, the modeled read time of its four anchor checks is about 18 µs. That figure counts reads only. The window that four appends must land in is the full duration of the scan, with its stamp checks, hashing and scheduling, and its length on a real machine is not measured. The four check passes of a read or of a scan read at most 288 KiB: at most nine checks in each pass, for eight marks and the anchor, and less than 8 KiB in each check. The allowance also bounds them. At 2 ms per KiB, 288 KiB of checks take about 576 ms past the slice deadline. One quantum can run the check passes of a scan and then those of the read that follows it, and both can run past the deadline. In the measured fixtures at 2 ms per KiB, check passes under a writer that appends every 20 or 21 ms run up to about 84 ms past the deadline, and every source finishes. When the slice deadline, cancellation, the allowance, or a new grown stamp ends a resumed scan after the anchor, the scan accepts the prefix without a check of every earlier mark at its own stamp. A rewrite under such a mark keeps the old facts under the same conditions when an append lands before that scan or during its checks. Two writes that change a block under a matched mark and return every stamp field to the saved stamp also let the next scan start past that mark. After a scan accepts the prefix, append parsing also needs an allowance above the 16 KiB reserve. A read that continues past a growth point can parse a record before a writer rewrites it. When the rewrite and an append land before the read ends and change no checked block, the read publishes the old record, and the old record stays under the same conditions. Total work has no aggregate bound. Continuous writes can prevent a whole-prefix comparison from finishing. Stamps and digests establish observed agreement, not an atomic snapshot. Metadata-preserving rewrites remain undetectable in some cases. Synchronous reads, oversized-record parsing, copying, and serialization have no hard latency bound.
