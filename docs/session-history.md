# Session history

[Session discovery](session-discovery.md) owns admission, repository scope, and relationships. [Data sources](data-sources.md#source-catalog) owns storage locations. [Retained rendering](panel-rendering.md#retained-rendering-contracts) owns browser node updates.

## Selected session history

A selected recorded session opens once the published catalog lists it. Otherwise it waits for ordinary discovery. Locally started drafts and accepted sessions retain host state until their records appear. Imported children receive no local awaiting-session ownership.

Selection starts with a bounded tail. Its loading payload precedes metadata work for other sessions. When the newest turn begins earlier, the worker scans disjoint older chunks for its boundary. Provider-specific adapters reduce 256 KiB chunks, observe cancellation between chunks, and create the accepted forward checkpoint. The host keeps their parser state opaque.

A completed prefix can publish when the same file grows during reading, then resume at the new revision. Append reuse validates physical identity and a bounded content anchor. Replacement, shrinkage, same-size rewrites, and incompatible identity discard affected work. Read failures retain drawable cards and show failed history status. Without cards, they show a diagnosis. Refresh or selection retries.

A selected window read stays reusable while its revision, turn and byte limits, workspace folders and Claude child relationships match. `claudeRelationshipKey` in `selectedsource.ts` builds the relationship key for both the host and the worker. Dispatched sessions are not part of that key.

A compressed rollout opens through its decoded body. Each window read hashes the `.jsonl.zst` file and decodes the whole body before the readers start, unless the worker holds the body of that hash. The host sends a window read once per selection, even when it holds a current window. Window and page reads then read the body at its held length. The held length equals the decoded length when no record is reduced or skipped. The worker decodes one body at a time, and only for a selected session. A read of another compressed path stops the running decode and waits until the reads of the current body end. The stopped window read runs again once in its selection. A second stop shows the read failure, and the host does not read that window again until the owner selects the session in any panel or the file changes. A window that another panel draws, a selection in another panel, or a read failure in another panel keeps that failure. The host records the file of each window or page read that opens a body, and releases that body when no selected session reads its file. A release names its file, and the worker ignores a release that names another file than the one it reads. A read whose file the host releases while the read waits does not keep the body that it decodes. Such a window read answers like a stopped window, and such a page read returns no page. A window whose body the host releases during its hash check or its read answers like a stopped window. A read of the released file waits until the reads of the released body end. A checkpoint or page cursor of another path or body hash does not serve a read. A decode that ends inside a zstd frame draws as a normal window, and the host reads it again after 10 s, 60 s and 600 s. A body above 512 MiB shows the failed history status.

A row whose rollout Codex compresses while Arc runs keeps its title, figures and cost through the [compressed rollout stores](#compressed-rollout-stores). Selection opens the `.jsonl.zst` file through its decoded body as above.

Older history uses semantic pages without enlarging or reparsing the ordinary tail. One request runs at a time, with one cursor per session. [`webview/history-control.ts`](../extension/src/webview/history-control.ts) owns automatic and explicit requests.

A page must establish both semantic edges before admission. A request containing only represented turns continues within a bound derived from loaded turns. Pages merge by stable turn identity. Each page retains target turns, an older guard, and required boundary records. Relevant turns can exceed a chunk. Irrelevant sparse lines do not accumulate.

Loaded pages survive only at their accepted revision or through revision-bound append provenance naming that revision. Catalog metadata never rebases or drops them during rendering. Truncation, replacement, or anchor mismatch resets pages after a stable retry. Semantic backward evidence stays separate from forward state.

A tail starting after byte zero excludes records touching its floor. Prompt or task starts decide turn membership even when associations reach earlier. Crossing required associations rebuilds the bounded tail. Generated titles survive trimming. Implicit compaction values expire with their source. Active turns can cross the byte window. Bounded tool pairing retains visible steps, so older unresolved results can become unpaired. Ambiguous pages use identity-only scans. Reaching byte zero finalizes that page's evidence.

An accepted append retains displaced completed turns in one bounded recent page. Its limit is the ordinary turn limit minus turns remaining in the tail. Explicit older pages stay separate. The selected cache budget bounds recent-page content except for one newest turn. A fresh panel starts from its bounded tail.

Accepted turns, source checkpoints, and older pages share `arc.sessionCacheMiB`. Selection protects the current session, including an oversized value. Optional sessions leave in least-recently-viewed order. Eviction preserves unread metadata and completed lifetime facts. [`historypages.ts`](../extension/src/historypages.ts) owns retention and eviction.

Session figures cover the tail plus loaded pages. Empty states describe selection, not the background parse set.

## Compressed rollout stores

[`compressedstore.ts`](../extension/src/compressedstore.ts) owns two stores that share one format. The workspace store holds title entries, openings and spend records. The machine store holds the openings that place a rollout in a workspace. [Data sources](data-sources.md#source-catalog) lists their directories. Only the worker writes them. Compressed facts never enter the derived title map or its checkpoint.

A holder takes the lease `backfill.lock` through `takeCodexOpeningsLock`. It renews the lease every 10 seconds: it reads the lock, compares the token and the `epoch` file, and touches the modification time. On a missing lock, it recreates the lock with an exclusive create. Another token, an overwritten `epoch` or a failed recreate ends the lease. A holder checks the lock and `epoch` before each publish, after each flush, after a recovery's listing, and after a compaction's manifest and before it retires the inputs. A failed check, a failed renewal or a store error starts an abandonment. The holder stops its writes, closes its open segment, and releases the lock on a token match. With work left, it waits a random 5 to 30 seconds and takes the lock again. A new holder writes `epoch` above the kept value and every epoch in a file name, and then resumes at the first entry it has not written. A check precedes each write to the lock or `epoch` as a separate operation, so a paused holder can remove the live lock once or overwrite `epoch` once. The live holder recreates a removed lock at its next renewal. An overwritten `epoch` makes both holders abandon within 10 seconds, and both retry after their waits. A panel hide and a lone cancelled request stop the worker, and a worker that opened a store releases its leases before it ends. A holder reports an entry as durable only after its line is flushed, the check after the flush passes, and the segment still exists by name. Otherwise the entry stays queued.

The holder appends each revision as one JSON line to its open segment and flushes before the next derivation. The segment, shard and manifest names are `segment-`, `shard-` and `manifest-<epoch>-<token>-<seq>`. Atomic writes name their temporary `<target>.<token>.<time>.tmp`. The open segment closes at 4 MiB, before a compaction and on abandonment. A record above 4 MiB gets its own segment file. An entry above 1 MiB drops its title entry and keeps a carried name and its cost.

Compaction runs only in the holder, at 32 closed segments of the current or an older fact version, or at most once per 300 seconds. It keeps the first-ranked entry per path, in pair-key order, and drops an entry whose two forms are both absent. Shards close at the first entry that brings them to 4 MiB. A manifest names its shards and inputs. A compaction whose input cannot be read ends without a manifest and removes the shards it wrote. Shards and manifests reach the disk before their inputs are deleted. Readers merge entries by fact version, then by a stat equal to the file, then greater modification time and size, then an entry with a decoded length, the higher epoch, the greater holder token and the later line in write order. A reader ignores a shard that no valid manifest names, skips an input that a valid manifest names, and skips an incomplete trailing line. A file of a newer fact version belongs to a newer build, and the holder never counts, takes or deletes it. A file of an older fact version is a readable stale candidate, and a compaction folds it into its shards. At a takeover, before any write of a shard, segment or manifest, the holder deletes every shard that no current manifest names, the older manifest, the inputs that the current manifest names, and every temporary of another token. Then its recovery compaction runs. The listing holds at most 72 names per fact version in steady state and 91 after a crash. Each visible panel lists the store every 10 seconds and reads only the bytes appended since, so an adoption in another window reaches this window without a restart.

A plain rollout that Codex compresses while Arc runs keeps its facts through adoption. The worker decodes only the first line of the twin, up to 1 MiB, for its opening. With the opening's thread id and modification time equal to the plain rollout's and a complete plain spend record, the worker takes the plain title entry, opening and spend record, hashes the twin and appends an entry. One stat of the twin covers the opening read, the hash and the entry, so a twin that a later compression replaces mid-adoption fails it. The row then lists the twin with those facts. A decode error, no line break within 1 MiB, a first line that is not an opening, an unequal thread id or modification time, or an incomplete plain record fails the adoption. A failed adoption discards the plain facts and records the twin with a mark that the backfill reads first. An adoption settles only when its entry is durable, and a current adopted entry settles a retried adoption. A twin of another revision adopts again. While an adoption is unsettled, title pruning and the opening trim keep the plain path, and the derived cache keeps it across a restart. An adoption waits for the load of the stores and the ledger's hydration. A listed plain twin gives no row but leaves its entry a ledger candidate. The host drops an entry whose two paths are both absent or out of scope.

A version change never removes a row that the store holds at an older fact version. Until a re-derivation, the host shows a carried name and the previous spend record counts. An entry of a newer fact version stays unread and untouched until a build that knows that version reads it. `COMPRESSED_FACTS_VERSION` joins the entry currency test with `CODEX_META_VERSION`, the Codex metadata generation and the Codex spend parser generation.

The host sends the worker its complete set of compressed names on `claude-children` until the worker answers a request that carried the current set. A superseded or cancelled request keeps the set unsent. The worker records the names without an entry for the backfill, in slices that yield to other requests, and it decodes none of them.

## Cache ownership

Agent records supply rebuildable metadata, parsed history, and spend. Reader-owned watermarks, pins, archive state, drafts, comments, open controls, and selection live separately in normalized VS Code state. Transcript retention determines historical timeline availability. Arc keeps no separate historical-turn archive.

| Cache | Reuse and ownership |
| --- | --- |
| Discovery metadata | Per-source opening, human-prompt, working-directory, and name evidence uses the revision that changes its answer. |
| Codex openings | Shared path-keyed `codex-openings.json` uses its independent opening generation. |
| Derived session metadata | Workspace entries retain names, starts, activity, classification, outcome, and bounded context by path, size, and modification time. Relationships and metadata have independent generations. The cache also keeps the links and child rows of the last complete discovery reply that settled membership, with its time, repository roots, discovery compatibility, and receipt store identity. A set of more than 65,536 links and child rows together is not saved. [Session discovery](session-discovery.md#session-discovery) owns the first catalog that publishes from them. The cache also keeps complete prompt scans of Claude transcripts. Each scan holds whether it found a prompt, its complete-line cursor, and the size, modification time, device and inode of the file it read. A scan that found no prompt and still holds a command is not saved. A scan that found a prompt is saved without its command. The cache keeps the scans of the most recently modified files up to `MAX_SAVED_PROMPT_SCANS`, 10,000. A cache file without saved scans loads none. [Session discovery](session-discovery.md#session-discovery) owns the rule that settles a row from a saved scan. |
| Selected history | File revision, parser options, folders, and descendant revisions qualify worker checkpoints and retained pages under one history budget. |
| Child usage | Worker-owned completed-child facts use child revisions and commit-placement scope. Parent reads carry descendant dependencies. |
| Project spend | Incremental source cursors and the last complete display ledger remain separate. Lifetime projection reuses the ledger revision. |
| Search | Explicit content searches populate compact text entries by path, size, and modification time. |

Discarding optional derived or opening caches triggers source reads. Trim metadata against a complete catalog, after Claude child discovery first answers. Earlier lists can contain only selected sessions. Workspace changes clear that catalog boundary. Metadata reuse comparing size and modification time cannot detect a replacement preserving both values.

A change to both advances both. A generation change drops that agent's incompatible entries but carries `label` and `fullLabel` until fresh metadata replaces each name. Carried names remain separately persisted across partial rebuilds. Recognizable incompatible entries can instead be rejected individually. Relationship interpretation uses `CLAUDE_CHILD_REFERENCE_PARSER_VERSION`. Opening derivation uses `CODEX_META_VERSION` in `codexopenings.ts`. Saved prompt scans use `PROMPT_SCAN_RULES_VERSION`, and a change to the prompt rules in `transcript.ts` advances it. A scan of another version does not load. Changing one does not invalidate the others. The Claude generation and `PROJECT_SPEND_PARSER_GENERATIONS` both version the turn boundaries a loop wake sets, so saved facts and saved `visibleTurns` and `closedTurns` rebuild with the rule.

`derived-session-cache-v2.json` separates format, the metadata generation of each agent, and per-entry relationship generation. Every title row names its agent. `sourceAgentOf` qualifies that agent by the Claude projects root and the Codex sessions root. An entry inside neither root or inside both keeps only its name. So does a row whose saved agent differs from its root.

Only current-path absence permits import of `derived-session-cache-v1.json`. Version 1 rows name no agent, so import takes each agent from its root. `V1_METADATA_GENERATIONS` maps the shared version of a version 1 file to agent generations. No shared version admits metadata for either agent. Version 1 relationships and scheduling follow the current-file rules. Import never rewrites the version 1 file, which stays for rollback. A build that writes version 1 never writes the current file. Only absence of both files permits legacy import. Known legacy versions 63 and 64 admit parser-26 relationships. Legacy metadata matches no current generation. Other current-file failures never fall back. Legacy scheduling restarts. Scope, semantic dependencies, retained cursors, and accepted relationship progress qualify continuation. Removing dependent rows or cursors discards scheduling state.

Migration requests a checkpoint without source growth and retries failed publication twice through the checkpoint timer. Imported opening seeds must reach atomic shared storage after an admitted walk before current-format publication, including shutdown. The openings writer resumes pending migration after publishing seeds. Bounded verified repository observations retain their independent format.

Codex opening changes require `CODEX_META_VERSION` changes, including derivation changes that preserve shape. This rereads machine-wide rollout heads. Unversioned derived cache versions 27, 28, and 29 identify opening generation 1. A metadata-generation change preserves compatible shared openings.

### Shared opening writes

Each opening save exclusively creates `codex-openings.json.lock`, reads shared rows, merges, and atomically replaces the file. Replacement and lock removal require its token. Lock contention retries after two seconds. Locks and takeover guards become stale at 30 seconds. Takeover rechecks lock text and modification time under a matching exclusive guard. A resumed previous holder with a changed token writes and removes nothing.

A holder paused between its final token check and rename can overwrite another window's rows. Startup rereads missing rows from rollouts. Saves retain existing rollouts and rows shared by disk and the latest walk. A deleted rollout absent from one side cannot return through older cache evidence. Missing or unreadable shared storage uses workspace opening seeds. A valid empty shared file does not use them. `saveCodexOpenings` owns merging and takeover rules.

### Folderless partitions

A folderless window allocates a unique path without creating it. The first cache write publishes ownership before data. Ownership survives panel closure. Provider disposal closes admission, flushes synchronous writers, then publishes release. Resumed writes allocate a fresh path and generation.

Every folderless write checks exact ownership bytes. Missing, unreadable, oversized, or replaced ownership blocks writes and release. Path checks do not prevent external replacement during a write.

Written folderless partitions remain on Windows, macOS, and Linux. Node pathname deletion cannot bind every ancestor and removed directory to validated identities. Linux boot differences remain uncertain without same-machine evidence. Windows lacks complete reparse-tag inspection. Windows and macOS lack precise process-lifetime inspection here. Reclamation performs zero filesystem operations and no process inspection. Unwritten activations leave no partition. Drafts and assets keep separate lifetimes.

## Search

[`turnsearch.ts`](../extension/src/turnsearch.ts) and [`domain/session-query.ts`](../extension/src/domain/session-query.ts) own content matching and snippets. Browser `search.ts` consumes results without reinterpreting query syntax.

Search reads an independent 16 MiB tail and can omit visible older pages. Scoped results report whether it reached the first turn. Explicit search alone populates the corpus. Labels, archive state, agent-run classification, and cached names update without reparsing unchanged text.

Numeric cost and cache-expiry filters do not narrow content results because entries contain neither fact. Entries also lack facts for unsupported state predicates. Prefix resolution uses accepted scoped identities before other filters narrow the pool. Incomplete discovery suspends unresolved prefixes. Identity-context changes re-evaluate retained entries. [Session list](session-queries.md#session-query-syntax) owns the query language.
