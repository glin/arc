# Session queries

Read this guide when changing session query grammar, identity resolution, or numeric comparisons. [Session list](rail-and-navigation.md) owns filter controls.

## Session query syntax

The session list filter accepts `id:`, `session:`, `agent:`, `title:`, `label:`, `cost:`, `cache-expiry:`, and `is:`. Bare words match title substrings. Labels match complete names with the shared case-folding rule. Double quotes enclose values with spaces. Two quotes inside a quoted value represent one quote. A leading `-` negates a term on any supported axis. Outside a session alternative group, every positive term must match, and every negated term excludes its matches. For example, `label:ui label:bug is:active` keeps Active sessions carrying both labels. A lone `-` or a word starting with two negation marks adds no term. A quote before a leading `-` keeps that mark as text. A quote at the start of an `id:` or `session:` word keeps it as title text, or content text after `find:`. A quote around the selector value, as in `session:"one"`, retains identity selection. A quoted word with another recognized prefix uses that prefix. Thus `"-fix"` searches titles for the hyphen, and `find: "-name"` searches content for it. `is:` completes input, unread, read, running, warm, active, needsyou, archived, and agentrun. No complete value is a prefix of another. Incomplete and unknown status words add no term. `is:archived` reads archived state independently of Show archived. `is:agentrun` reads agent-run identity independently of the displayed bucket. `is:warm` tests prompt-cache lifetime against the browser clock, including archived sessions and agent runs. `is:active` tests that lifetime or activity within the last hour against the same clock. `is:needsyou` keeps sessions matching `is:active` that need input or are unread. `domain/session-query.ts` owns grammar, caret tokens, and matching. `view/session-query.ts` owns query notes and label suggestions.

`id:<ID>` and `session:<ID>` select native Claude or Codex session identities. Add `claude:` or `codex:` before the ID to restrict the provider. Provider names ignore case. Native IDs preserve case. Exact IDs take precedence, including short IDs. Canonical 36-character UUIDs always match exactly. Other values of at least eight characters expand to every matching identity in the complete scoped catalog. Shorter values match exactly. Duplicate source files retain their rows but count as one provider identity. Unknown IDs match no sessions. Paths supply no identity aliases.

Repeated positive `id:` terms select their union, including when other axes separate them. Explicit adjacent positive OR chains containing `id:` join that union. Standalone `session:` terms and session-only OR groups retain AND semantics. Negative selectors exclude globally. Prefix resolution includes archived and hidden sessions before other filters narrow results. The existing query note reports ambiguous prefixes and their distinct session counts. Incomplete or unavailable discovery suspends unresolved prefix queries, including negative queries, without changing saved text. Matching resumes when discovery completes. Exact-only queries retain ordinary matching and coverage.

Uppercase unquoted `OR` joins adjacent positive session selectors into one alternative group. For example, `label:arc session:claude:one OR session:codex:two` requires the label and either identity. Other terms and separate groups retain AND semantics. Negated session selectors exclude matches globally. Duplicate alternatives never multiply rows. Bare `OR` without adjacent selectors, quoted `OR`, and lowercase `or` remain text. Content search uses the same identity selection.

Empty or malformed selectors empty the list, including negated selectors. Dangling, doubled, mixed-axis, and negated-selector OR chains also empty it. The filter box displays correction guidance. Session selection preserves Show settings, so archived sessions and agent runs remain subject to their existing visibility choices.

`cost:>5.43` keeps a session whose recorded USD cost is greater than the threshold. `cost:<5.43` keeps one whose exact recorded cost is less than the threshold. A cost value requires one strict `<` or `>` operator followed by a non-negative whole or decimal number. A session with no recorded cost matches neither comparison. A lower-bound cost matches `>` only when its recorded amount already exceeds the threshold. It never matches `<`, because the unknown remainder can cross the threshold. A negated cost term keeps every session its comparison drops, which includes a session with no recorded cost and a lower bound that has not crossed a `<` threshold. An invalid cost value remains in the query, empties the session list, and receives a visible correction from the filter box.

`cache-expiry:>0` keeps sessions with more than zero exact cache-expiry returns. `cache-expiry:<3` keeps sessions with fewer than three. Values use the strict non-negative comparison grammar described for `cost:`. Unavailable or unindexed facts match neither comparison. A lower-bound count matches `>` only when its known amount exceeds the threshold. It never matches `<` because unclassified request pairs can increase the count. Negation keeps every session the positive comparison drops, including unavailable facts and lower bounds. An invalid value remains visible, empties the list, and receives a correction in the filter box. `sessionCacheFactsBySession` in `extension/src/projectspend.ts` supplies lifetime primary-session facts. The filter reads them from the Session list card without scanning requests. The card displays no cache-expiry figure.
